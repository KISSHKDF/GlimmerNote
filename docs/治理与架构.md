# 治理、架构与路线（单人维护项目的"制度写在纸上"）

> 为什么要有这份文件：本项目是**单人维护**，最容易的错觉是"规矩都在我脑子里，不需要写"。
> 但审计判据（GSE-STD A-01/A-02/A-03/A-05）问的是**外部读者能不能查到**——查不到就等于没有。
> 本文件只写"谁拍板、怎么拍、做什么、不做什么、系统长什么样"。**具体流程**在 `CONTRIBUTING.md`，**契约规则**在 `docs\作答契约.md`，此处不重述（一份事实只住一个家）。

## 一、维护者与角色（对应 A-01）

| 角色 | 谁 | 负责什么 |
|---|---|---|
| **维护者（唯一）** | 本仓库的所有者（`git log` 的作者） | 全部代码、数据契约、发布决策、安全响应 |
| 贡献者 | 任何提 PR 的人 | 按其 PR 范围负责；合入需维护者审核 |

**联系方式**：本仓不公布个人邮箱。渠道一律走托管平台（**这也是隐私取舍，不是遗漏**）：

```powershell
# 本仓的托管地址就是唯一权威渠道
git remote get-url origin
```

- **缺陷 / 需求** → 该地址的 Issues（模板会强制填版本号、复现步骤、期望结果）
- **安全漏洞** → 该地址的 Security → Private vulnerability reporting（**不要公开提 Issue**，详见 `SECURITY.md`）

## 二、决策机制（对应 A-02）

**谁拍板**：维护者一人拍板。单人项目的"投票"是伪装的共识，写清反而更诚实。

**怎么拍**（按变更的影响面分档）：

| 档 | 例子 | 决策方式 |
|---|---|---|
| **不可逆** | 改 `数据\` 的 schema、换版本号方案、删历史、推远端、打 tag、改许可证 | **必须先明确同意再做**；不接受"先做了再解释" |
| **对外可见** | 发布包内容、`README` 承诺、`SECURITY.md` 时限、配方正文 | 写进 `CHANGELOG` 对应条目；**改动正文要极慎重**（`docs\配方规范.md` 同理） |
| **内部** | 重构、注释、测试补强、文档措辞 | 直接做；走门禁即可 |

**争议怎么解**（本项目真正发生过的一类）：当"我"和"我的另一个判断"冲突时，以**可复算的证据**为准，不以记忆或直觉为准：

1. 先写复现命令，跑两次，贴逐字输出；
2. 两个结论矛盾时，**找判据的边界反例**（构造一个能让其中一个结论变红的最小输入）；
3. 仍不能裁决 → 记为 `未决`，写进 `CHANGELOG` 或对应文档的"已知边界"节，**不留一个看起来像结论的猜测**。

> 这条不是空话：本仓历史事故多数来自"静默降级"——失败被讲成成功、缺省值掩盖错误。见 `AGENTS.md` 末条。

## 三、路线（对应 A-03）

> **本路线不绑日历**。节奏是"做完一件、有空做下一件"，不用"本周/下月/年内"表达进度。
> 里程碑编号 `N1/N2/N3`（沿用本仓既有习惯），编号只表示顺序，不表示时间。

### N1 · 能交付（当前所处阶段）

把"公开发布给陌生人使用"这件事**做完**，而不是做完功能：

- [ ] 建立公共托管仓库（`scripts\setup-remote.ps1`，强制过门禁、拒脏工作区）
- [ ] 开启 Issues（含 `config.yml` 禁止空白 issue）+ 私密漏洞报告
- [ ] 上传发行包到 Release（`release\` 里的 zip 与 `.sha256`，正文抄 `CHANGELOG` 该版本条目）
- [ ] 每个发布补 git 附注标签（**当前 30 个包只有 2 个 tag**）
- [ ] 清理 `docs\等级与NA清单.md §五` 里剩余的阻断项

### N2 · 能维护

让"下一个人（或下个我）"能接手：

- [x] `CONTRIBUTING.md`（分支/提交/回退三层/禁止事项/自检）
- [x] `AGENTS.md`（给 AI 协作方的最小作业面）
- [x] 版本化门禁钩子（`.githooks/`，新克隆可一条命令装上）
- [x] 严格性等级声明与 N/A 清单（`docs\等级与NA清单.md`）
- [ ] 托管 CI：每次推送自动跑 `lint` + `fixture`（本地门禁只能管自己这台机器）
- [x] 门禁自加固：`tools\lint.mjs` 已覆盖 **9 类**（L1 语法 / L2 本机绝对路径 / L3 行尾空白 / L4 调试残留 / L5 编码 BOM / L6 行尾与 `.gitattributes` 一致 / L7 CHANGELOG 逐版字段 / L8 端口只许出自真源 / L9 替换字符 U+FFFD 哨兵）
- [ ] 静态分析接入（lint 是**手写规则**，不含通用静态分析器的安全规则；见 `docs\等级与NA清单.md` 的 G-03/G-04）

### N3 · 能规模（**非目标**）

明确不做，理由见 `docs\等级与NA清单.md §一`：单人、无监管场景。
真要做时需要的是：多人评审、覆盖率门禁、SBOM/来源证明、行为准则——**在有人一起维护之前，做这些只是给自己加仪式**。

## 四、明确**不做**的事（对应 A-03 的"不做清单"）

> GSE-STD A-03 要求路线图含"不做"清单。**写"不做什么"比写"做什么"更能防止跑偏。**

| 不做 | 为什么 |
|---|---|
| **不联网、不上传、不做账号体系** | 这是本项目的存在理由（`README.md` 首段）。任何"顺手加个云同步/在线题库"的提议都与此冲突。**联网边界的分阶段精确说明见 `README.md §联网情况`。** |
| **不内置 AI、不带 API Key** | 程序不带大脑：录题靠"配方"（纯文本提示词 + 输出契约），交给用户自己的 AI 执行。见 `docs\配方规范.md`。 |
| **不让终端用户编辑配方** | 配方随包发布，只读。理由与替代方案（PR / 提 Issue）见 `docs\配方规范.md §八`。 |
| **不引入运行时第三方依赖** | 零 `node_modules`。这条保护的是"绿色免安装 + 数据全本地"，不是洁癖。 |
| **不做跨平台** | 桌面壳依赖 WebView2 + Windows 自签证书链路；跨平台要重写壳与打印链路，收益不抵成本。 |
| **不做多用户/多机协同** | 与"完全离线 + 数据是本机文件"冲突。 |
| **不用分支表达版本** | 主干开发，版本由 `VERSION.json` + tag 表达。理由见 `CONTRIBUTING.md §一`。 |
| **不改写历史** | `reset --hard` / 强推 main 会切断"归档件 ↔ 源码"的对应关系，2026-10-23 真实发生过一次事故。见 `CONTRIBUTING.md §三/§四`。 |

## 五、架构高层视图（对应 A-05）

```
┌──────────────────────────────────────────────────────────────────┐
│  用户（家长/孩子）                                                 │
└───────────────┬──────────────────────────────────────────────────┘
                │ 双击 拾光小册.exe
                ▼
┌──────────────────────────────────────────────────────────────────┐
│  桌面壳  src\shell\CTBShellV2.cs  （C# / WebView2）                │
│  · 单实例互斥体 · 自签证书 · 打印接管 · 导航白名单                  │
│  · 按名字调 node.exe 跑 app\tools\ 里的 .mjs，把结果回给页面        │
└───────────────┬──────────────────────────────────────────────────┘
                │ 本地 HTTP（仅 127.0.0.1，端口见 _服务端.mjs）
                ▼
┌──────────────────────────────────────────────────────────────────┐
│  界面层  src\app\js\  （纯前端，只读 _状态.json，不加工数据）        │
│  视图：今日总览 / 复习流 / 题库浏览 / 组卷工作台 / 待办 / 统计       │
└───────────────┬──────────────────────────────────────────────────┘
                │
                ▼
┌──────────────────────────────────────────────────────────────────┐
│  内核  src\tools\*.mjs  （23 个命令行工具，零第三方依赖）           │
│  · 真源读写：_安全写.mjs（临时文件 + fsync + rename 原子写）        │
│  · 门禁/裁判：_作答门禁 · _配图门禁 · _原卷台账 · _着重号门禁        │
│  · 日常操作：_标记复习（组卷/批改/归档）· _待确认 · _盲解复核 · _体检 │
└───────────────┬──────────────────────────────────────────────────┘
                │
                ▼
┌──────────────────────────────────────────────────────────────────┐
│  数据（唯一真源，全在本机）                                         │
│  <库根>\_索引.json  每学科每学生一条，卡片与复习字段的权威            │
│  <库根>\_状态.json  派生缓存（界面只读它；可随时重生成）              │
│  <库根>\各台账      待确认 / 组卷 / 配图 / 原卷 / 笔形 / 盲解双路      │
│  影像：按内容寻址落盘（见 docs\路径规范.md）                        │
└──────────────────────────────────────────────────────────────────┘

旁路（不进程序，只在开发/发版时用）：
  src\recipes\   配方（AI 方法层，纯文本，随包发布但只读）
  scripts\       build-release → deploy → rollback / fetch-deps / selftest-pipeline
  tests\         门禁（run.mjs 是唯一入口：fixture / quick / full 三档）
  fixtures\      合成测试库（绝不含真实用户数据）
```

**图与文字的分工**：上图给"有哪些块、谁调谁"；**每个块内部怎么不撒谎**（比如"没找到"与"空"必须分开）写在 `docs\作答契约.md`、`docs\发布链路.md`、`docs\路径规范.md` 里。

### 5.1 三层的职责边界（最容易越界的地方）

| 层 | 只做 | **绝不**做 |
|---|---|---|
| **内核**（`src\tools\`） | 数据、台账、门禁、渲染数据 | 不认识任何一道题、任何学科（"可插拔"的前提） |
| **配方**（`src\recipes\`） | 告诉外部 AI 怎么识别、怎么判错 | 不被程序改写；不含学生数据、不含 API Key、不联网 |
| **界面**（`src\app\js\`） | 只读 `_状态.json` 并展示 | 不加工数据、不直接写盘（写盘一律走壳 → `app\tools\`） |

## 六、维护者失能后怎么办（对应 A-06）

GSE-STD §6 对 A-06（连续性方案）给的 N/A 条件是「单人、无他人依赖」——本项目符合，故本条 **N/A**，理由已记入 `docs\等级与NA清单.md §四`。

但**有一条不因 N/A 而免除**，写在这里以免真出事时没人知道：

- 本项目的"资产"是**本机目录**（开发区 + 运行区 + 数据）。**唯一的异地副本**是用户自己的备份习惯；一旦托管远端建立，`git` 会提供第二份源码副本，但**用户数据（`数据\`）永远只在异地备份里**。离机影像镜像的现状与缺口见 `docs\等级与NA清单.md §五`。
