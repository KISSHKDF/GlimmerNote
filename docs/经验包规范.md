# 经验包规范（可插拔方法层）

> 立：2026-11-03（批次 2）｜引擎：`src\tools\_经验包.mjs`（唯一读取/校验入口，**只读**）
> 本文是 `_经验包.mjs` 每个子命令与字段的**登记处**（"一份事实一个家"）。
> 区域坐标（`x/y/w/h`、`role`、`pageSha`、`imgW/imgH`）的口径**不在本文**，真源是 `docs\区域契约.md`。

## 一、为什么有这一层

内置配方（`src\recipes\`）随程序发布，**内核不认识任何一道题**；它承诺完全离线，也不能因为
"某类题现在更容易听懂另一种说法"就发一次版。

经验包把**一条可公开的方法**装成独立文件夹：能装、能选、能停、能回退，而且**坏包只影响自身**
（清单照常列、内置配方照常可用）。

三条边界（与建议书 §5 一致）：

1. **首版没有安装命令**：安装＝把一个文件夹**手工复制**到经验包根下面。少一条写路径，就少一个
   "静默写错地方"的面。
2. **停用即回退**：包目录里放一个 `.停用` 文件即停用，删掉即恢复。没有"卸载""降级"这类新动作。
3. **完全离线**：包内路径出现外部 URL 一律拒；引擎不联网、不下载、不执行包内任何内容。

## 二、磁盘布局

```
<经验包根>\<packId 的斜杠逐段展开>\<version>\pack.json
                                                \cards\<cardId>.md
                                                \cases\<caseId>\input.svg
                                                \cases\<caseId>\expected.json
                                                \README.md
                                                \.停用            ← 可选：存在即"已停用"
```

- **packId** = 包目录相对「经验包根」去掉最后一段 `<version>` 后的斜杠连接（例 `family-a/shared-stem`）。
- **version** = 包目录的最后一段，形如 `1.0.0`（数字.数字.数字）。
- 目录名与 `pack.json` 的 `id` / `version` **必须一致**（`校验` 会对账；不一致 ⇒ 结构性错误，exit 1）。
  为什么必须对账：同一个包否则会有两个身份——清单按目录名报、选卡串按目录名找、`pack.json` 又写着另一个。

### 经验包根（`packsRoot()` 解析顺序，唯一实现）

| 顺序 | 来源 | 说明 |
|---|---|---|
| ① | `--packs <dir>` | 显式，最高优先（测试一律用它） |
| ② | 环境变量 `CTB_PACKS` | 机器级/会话级覆盖 |
| ③ | `%LOCALAPPDATA%\拾光小册\经验包\` | 默认；读不到 `LOCALAPPDATA` 时回落 `<用户主目录>\AppData\Local\拾光小册\经验包` |

**为什么默认放 `%LOCALAPPDATA%`**：经验包是**用户装的东西**，不是程序资产。放进仓库会让"我装了什么"
跟着 git 走，还会被发布包一起打包出去；放进用户的 `数据\` 又会让只读工具碰到用户库。

## 三、`pack.json` 字段

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `formatVersion` | ✅ | 整数，**只认 `1`** | 未知版本**一律拒**（不同版本字段语义可能不同，猜着读＝静默降级） |
| `id` | ✅ | 段用 `/` 分隔，每段 `[A-Za-z0-9._-]` 且首字符不是 `.` | 与目录推出的 packId 必须一致 |
| `version` | ✅ | `数字.数字.数字` | 与目录最后一段必须一致；**版本号是内容的身份** |
| `cards` | ✅ | 非空数组 | 空数组＝没有卡的经验包，拒收 |
| `cards[].id` | ✅ | 单段 `[A-Za-z0-9._-]`，首字符不是 `.`，不含 `/` 与 `@` | 同包内**必须唯一**（否则选卡串指代不明） |
| `cards[].body` | ✅ | 包内相对路径 | 指向方法正文（Markdown）；会进提示词 |
| `cards[].steps` | ⬜ | 字符串数组 | 本卡覆盖了内置配方的哪些步骤（例 `["整页拆分"]`）；用于步骤冲突判定 |
| `cards[].cases` | ⬜ | 字符串数组 | 每项是包内相对目录，里面必须有 `input.svg` + `expected.json` |
| `cards[].title` | ⬜ | 字符串 | 缺省时回落到包 `title` |
| `title` / `author` / `license` | ⬜ | 字符串 | 清单会展示；缺了只是列空，不算错误 |
| `changelog` | ⬜ | 数组 | 建议每条 `{ version, note }`，说清改了什么、为什么 |

案例目录里两个文件都是**必需**的：

- `input.svg`：合成案例的原页（**不要放真实试卷**）。
- `expected.json`：期望结果，必须是**合法 JSON**。它的内部结构（尤其 `regions`）按
  `docs\区域契约.md` 的口径写；本引擎只保证"文件在、能解析"，**不重复实现一份区域判据**。

## 四、选卡串

```
<packId>/<cardId>@<version>          例：family-a/shared-stem/shared-stem@1.0.0
```

形状判据（**与 C# 壳 `Recipe()` 的形状门禁是同一条，不是两套口径**）：

```
^[A-Za-z0-9_-][A-Za-z0-9._-]*(/[A-Za-z0-9_-][A-Za-z0-9._-]*)+@[0-9]+\.[0-9]+\.[0-9]+$
```

解析规则：按**最后一个** `@` 切出 `version`；剩余部分按 `/` 切，**最后一段 = cardId**，前面全部 = packId。
⇒ 由此得到三条约束：`cardId` 不含 `/` 与 `@`；`packId` 至少一段；`version` 形如 `数字.数字.数字`。

**为什么每段首字符不许是 `.`**：首版字符类写成 `[A-Za-z0-9._-]+`，于是 `..` 段天然合法，
`../evil/card@1.0.0` 能整条通过形状门禁（2026-11-03 在真 exe 反射测试里当场抓到）。
专家口径：**形状判据是第一道，realpath 包含性是第二道，两道互不替代**。
回归锁：`tests\neg-pack-contract.cjs` 第二节。

## 五、启用 / 停用

- 包目录内存在 `.停用` ⇒ **已停用**。内容随意，建议写停用原因（`--card` 命中它时会把第一行原样带出）。
- 停用是**状态**，不是"内容不合法"：停用包的 `校验` 仍然 **exit 0**（并给一条 note）。
- 选卡命中已停用包 ⇒ `loadCard` 返回 `code:2 / reason:'pack-disabled'`，原因里写明恢复办法（删掉文件）。
- **不引入任何写入子命令**：停用/恢复都是用户手工放/删一个文件。

## 六、安装、更新、回退

| 动作 | 怎么做 | 判据 |
|---|---|---|
| 安装 | 把包文件夹手工复制成 `<经验包根>/<packId>/<version>/` | `清单` 能看到 + `校验` exit 0 |
| 更新 | 复制成**新的 version 目录**（旧的保留） | 两份并列留存，选卡串写清用哪一版 |
| 回退 | ① 换回旧版本目录（选卡串改 version）② 或直接停用出问题的那版（放 `.停用`） | 见 §五 |
| 改内容 | **必须**改新版本号 | 沿用同一 `id@version` 但内容变了 ⇒ `校验` 报"同版异内容"（exit 1），并给两侧摘要前 12 位 |

**「同版异内容」为什么要报**：装的人以为拿到的是同一份，实际两份不同；回退时也说不清退的是哪一份。

## 七、安全判据（四道，互不替代）

包内每个被引用的路径（`cards[].body`、`cards[].cases[]`，以及案例目录里的两个固定文件）都要过：

| # | 判据 | 拒绝的形态 |
|---|---|---|
| ① | 形状 | 外部 URL（`^[a-zA-Z][a-zA-Z0-9+.\-]*:` 或 `//` 开头）、绝对路径（含盘符） |
| ② | 字符串包含性（`_路径护栏.mjs` 的 `isInside`） | `..` 越出包根 |
| ③ | realpath 包含性 | **重解析点逃逸**：junction / 符号链接指向包根之外 |
| ④ | 存在性 | 文件/目录不存在、`expected.json` 读不成 JSON |

为什么 ③ 不能省：② 是纯字符串判据，对"路径还在包内、真实指向包外"的 junction **看不出来**
（`tests\neg-pack-contract.cjs` 第七节有对照断言证明这一点）。

**边界（写清楚，别假装没有）**：包含性判据以**包根的真实路径**为界。如果**包根本身**就是重解析点
（有人把 `…\<packId>\<version>\` 做成指到另一个盘的 junction），那不算"逃逸"——它的真实路径就是包根，
包内引用仍必须落在其中；`清单` 会把它照常列出来（不因为"它是链接"就静默消失）。
包**内部**任何一层指向包根之外的链接才判红。

## 八、限值

| 常量 | 值 | 口径 |
|---|---|---|
| `MAX_FILES` | 64 | 包内**非隐藏**文件数（隐藏＝`.` 开头，如 `.停用`；`pack.json`/`README.md`/卡/案例文件都算） |
| `MAX_FILE_BYTES` | 262144（256 KiB） | 单个文件字节数 |
| `MAX_PACK_BYTES` | 1048576（1 MiB） | 整包合计字节数 |

超限一律报**实际数字**（不写"过大"）。整包内容摘要（`packDigest`）＝ 非隐藏文件按相对路径排序后
逐条 `rel \0 sha256(字节) \0` 再取 sha256；它只用于"同版异内容"判定。

## 九、校验错误分类与退出码

`errors[]` 每项 `{ code, what, why }`：`what` 指向具体位置（如 `cards[1].body`），`why` 是**具体原因**
（带实际路径/数字/两侧摘要），不是一句"校验失败"。

| `code` | 何时 | 例子 |
|---|---|---|
| `参数` | 包目录不存在/不是目录 | `包目录：不存在或不是目录：…` |
| `结构` | `pack.json` 缺失/非 JSON；`formatVersion` 之外的结构问题；`cards` 形状；目录与 `pack.json` 对账；案例 `expected.json` 非 JSON | `cards[1].id：缺 id` |
| `未知版本` | `formatVersion !== 1`（含缺失） | `只认 1，收到 2` |
| `重复` | 同包内卡 id 重复 | `卡 id 重复："shared-stem"` |
| `缺文件` | 卡正文/案例目录/`input.svg`/`expected.json` 不存在或读不出 | `案例缺 expected.json：…` |
| `越界` | 绝对路径、`..` 越界、外部 URL、重解析点逃逸 | `重解析点逃逸（junction/symlink 指向包根之外）` |
| `限值` | 文件数 / 单文件体积 / 整包合计超限 | `包内数据文件 68 个 > 上限 64 个（MAX_FILES）` |
| `同版异内容` | 同 `id@version` 已安装但内容摘要不同 | 给两侧摘要前 12 位 + "应改用新版本号并列留存" |

退出码：

| 子命令 | 退出码 |
|---|---|
| `清单` | **0**。包根不存在/为空也 exit 0（打印「没有安装任何经验包」）；坏包只让它自己那一行判红 |
| `校验 <dir>` | 0 通过 · 1 内容不合法 · 2 参数或环境错（目录不存在、子命令不认识、`--packs` 缺值） |
| `摘要 <dir>` | 0 成功 · **1 包不合法**（拒绝输出"看起来正常"的摘要）· 2 参数或环境错 |

> ⚠ `摘要` 的 1 是**刻意的加严**（契约 §2.1 的表只写了 0/2）：坏包若被打印成一份正常摘要，
> 等于把坏包当好包，正是本仓最忌的静默放过。已回报 Lead。

## 十、CLI

```
node src\tools\_经验包.mjs 清单   [--json] [--packs <dir>]
node src\tools\_经验包.mjs 校验 <dir> [--json] [--packs <dir>]
node src\tools\_经验包.mjs 摘要 <dir> [--json] [--packs <dir>]
```

`--json` 形状（`校验` 与 `摘要` 同族；`摘要` 额外带 `digest` / `digestShort` / `bodySha256Short`）：

```json
{ "ok": true, "dir": "…", "id": "family-a/shared-stem", "version": "1.0.0", "formatVersion": 1,
  "cards": [{ "id": "shared-stem", "body": "cards/shared-stem.md", "bodySha256": "<64 hex>",
              "steps": ["整页拆分"], "cases": ["cases/shared-stem"] }],
  "errors": [{ "code": "越界", "what": "cards[0].body", "why": "…" }], "notes": [] }
```

`清单 --json`：`{ "ok": true, "root": "<经验包根>", "packs": [ …listPacks() 结果… ] }`。

`bodySha256` 是**正文文件字节**的 sha256（不剥 BOM、不做换行归一）；本仓文本一律 UTF-8 无 BOM + LF，
所以与"正文文本的 sha256"等价。

## 十一、库导出（供 `_配方.mjs` 用，形状已由契约 §2.2 冻结）

```js
export const PACK_FORMAT_VERSION = 1;
export const MAX_FILES = 64, MAX_FILE_BYTES = 262144, MAX_PACK_BYTES = 1048576;
export function packsRoot(explicit);          // → 绝对路径（不做存在性检查）
export function parseCardSel(s);              // → { ok, packId, cardId, version, why }
export function listPacks(explicitRoot);      // → [{ id, version, dir, enabled, verdict:{ok,errors[]}, title, author, license }]
export function loadCard(sel, explicitRoot);  // → { ok:true, card:{ packId, cardId, version, body, bodySha256, dir, steps, cases, title } }
                                              //   | { ok:false, code:2, reason, why }
export function validatePack(dir, explicitRoot?); // → { ok, dir, id, version, formatVersion, cards, errors, notes }
```

- `loadCard` 失败的 `reason`（机器可读短码，便于调用方分别处置）：
  `sel-format` / `packs-root-missing` / `pack-unknown` / `version-unknown` / `pack-disabled` /
  `pack-broken` / `card-unknown`。`code` 一律 `2`。
- `listPacks()` 返回的 `dir` 是**绝对路径**；界面要显示的「来源」＝ `path.relative(packsRoot(), dir)`
  （口径就这一条，别在 UI 侧另算一种）。`packsRoot(explicit)` 收到相对路径时按**当前工作目录**解析。
- ⚠ 本模块**不在导入期**求值 `libraryRoot()`：它不依赖用户库（没有库也要能 `清单`/`校验`），
  导入期求值还会抢在 `--data` 落进 `CTB_DATA` 之前把库根定死（2026-10-31 真实事故）。
  回归锁：`tests\neg-pack-contract.cjs` 第十一节。
- ⚠ 本模块**只读**：不写用户库、不写经验包根、不做安装。

仓库内样本（**不随发布包分发**；安装＝手工复制这个文件夹）：


| 项 | 值 |
|---|---|
| `packId` | `family-a/shared-stem` |
| `version` | `1.0.2` |
| `license` | `CC-BY-4.0` |
| 卡 | `shared-stem`（覆盖步骤 `整页拆分`） |
| 选卡串 | `family-a/shared-stem/shared-stem@1.0.2` |

> **这个包的版本史（两条都是"规范第九节那条规矩"的实例，故意留着当活样本）**：
> · **1.0.0 → 1.0.1**：1.0.0 的合成案例把红色「✘ 批改：错」与上一行说明文字放在**同一基线且 x 重叠**，
>   渲染出来读成「0.1✘A)批改: 错」—— 而这份素材正是给家长判断「脱离原页能否读懂」用的，压字会把判断带偏。
>   修的时候**没有**就地改 `1.0.0`：`校验` 当场判红「同版异内容」（并给出两侧摘要前 12 位），
>   于是按规范新建 `1.0.1` 并列留存。区域契约与坐标**未变**（仍在 y 0.5~0.65 内），只有 `pageSha` 更新。
> · **1.0.1 → 1.0.2（家长人工判断回流，本批最重要的一条修正）**：家长看裁出的两块区域后给的判断是
>   > 「能看懂，但原因是因为你在红色卡片的括号中写了错误原因；**如果不写那一段话，是看不懂的**。」
>
>   也就是说：**区域本身（题干+作答+批改痕迹 & 公共条件）并不足以独立读懂**——真正让它可读的是"为什么错"
>   那段文字，而**真实卷面通常没有那段文字**（老师多半只画一个叉）。1.0.2 因此给卡加了第 5 步与
>   「区域只管卷面事实，错因必须写进记录字段」一节，并新增 `mark-without-text` 对照。
>   区域契约与坐标**未变**；`cases/*/expected.json` 的 `parentCheck` 记下原话与回流结论。
| 案例 | `cases/shared-stem`：一页合成实验题，(1) 已答对、(2) 错且依赖公共题干 ⇒ 只登记 (2)，区域＝(2) 的「错误位置」+ (1) 那条条件的「公共条件」；三个对照：小问互不依赖时不扩大区域、条件在未提供的下一页 ⇒ 标「待确认」、**批改痕迹只有符号没有文字 ⇒ 错因必须写进记录字段** |

**职责边界**：B-07「同一道题拆成两条」的基本保护**留在内置配方**（`src\recipes\ingest-page\anti-patterns.md`），
试点卡只补内置配方没有的"区域怎么定"。两边的分工写在 `docs\配方规范.md`。

## 十三、已知边界（写清楚，别假装没有）

1. **不安装、不写盘**：没有 `安装`/`停用`/`导入 zip` 子命令。要装就手工复制文件夹。
2. **不联网**：外部 URL 一律拒；引擎不做任何网络访问。
3. **不执行包内内容**：包里的文本只会被拼进提示词，不会被当代码/脚本执行。
4. **不判断方法好不好**：本引擎只判"形状/边界/限值/一致性"；质量好坏靠启停对照（批次 2 之后的质量验收）。
5. **不重复实现区域判据**：案例 `expected.json` 的 `regions` 口径在 `docs\区域契约.md`；本引擎只保证它是合法 JSON。
6. **`清单` 不是门禁**：它是报告。坏包在清单里判红，但整体 exit 0 —— 否则用户只是装错一个包，就再也看不见自己装了哪些包。

| 子命令 | 语义 | 退出码 |
|---|---|---|
| `白名单 [--json]` | 列出允许导出的字段与**显式排除**清单（自证"从零组装"） | 0 |
| `预览 <源> [--json]` | 组装草稿并打印全文 + 隐私扫描结论；**不写盘** | 0 通过 / 1 扫出私有标记 / 2 参数或环境错 |
| `导出 <源> --out <文件> [--form local\|cloud] [--json]` | 写草稿到**用户显式指定**的路径（父目录必须已存在；本工具不建目录） | 同上 |

`<源>` 两种，**互斥**，必须给且只给一种：

- `--card <packId>/<cardId>@<version>`：已安装的经验包卡（选卡串形状与包根解析**复用** `_经验包.mjs`，
  不另写一份）；可选 `--case <案例id>` 带上一个合成案例。
- `--from-pending <Txxx>`：`<库根>\_待确认.json` 里的一条 **`经验线索`**（库根按 `--data` → `CTB_DATA` 解析）。

通用参数：`--packs <经验包根>`（解析顺序见 §二）、`--data <库根>`。

判红（exit 1）时**拒绝写盘**，且 `--json` 里**不给草稿全文** —— 预览屏与 stdout 也是外发通道
（会被复制/贴图），把夹带内容整份打上去等于换个地方泄漏；报告只给命中处的上下文片段。

### 14.2 字段白名单（**从零组装**）

做法：草稿对象**从 `{}` 开始**，只把下表字段搬进去；源里任何不在表里的字段**默认丢弃**。
这不是"过滤黑名单"——黑名单的失败模式是"夹带出门"（看不见），从零组装的失败模式是"少搬了"（看得见）。

| 字段 | 从源里的哪里搬 |
|---|---|
| `方法正文` | 卡的正文文件（原样文本） |
| `步骤` | `pack.json` 的 `cards[].steps` |
| `适用条件` | 卡正文里「适用条件 / 什么时候用」小节（抽不到就**不搬**，不编） |
| `反例` | 合成案例 `expected.json` 的 `controls[]` |
| `预期行为` | 合成案例 `expected.json` 的 `expected`（登记/不收的小问、区域角色与理由；**不搬坐标与哈希**） |
| `合成案例` | 案例目录的 `input.svg` + `expected.json`（原样文本，见 §14.4 的唯一例外） |
| `配方id` / `配方版本` / `配方指纹` | `pack.json` 的 `recipe.id/version/fingerprint`（源里没声明 ⇒ 草稿不含这三个字段） |
| `作者` / `许可` | `pack.json` 的 `author` / `license` |
| `包id` / `卡id` / `包版本` | 选卡串解析结果（与 `pack.json` 的对账由 §九 的 `校验` 负责） |
| `生成时间` | 本工具生成（本机时区 ISO 8601） |
| `工具版本` | 程序目录的 `版本.json`；开发区回落到仓库 `VERSION.json`（都读不到 ⇒ 字段写「未知」并打印 ⚠） |

**显式排除**（列出来是**可核对的承诺**，不是实现细节）：孩子原图（任何图片字节）、真实哈希、
家庭路径、聊天原文、手写批注、任务全文、学生/家长标识。

`--from-pending` 的映射（待办不是包，来源不同）：

| 草稿字段 | 从待办条目的哪里搬 |
|---|---|
| `方法正文` | `detail`（家长原话所在字段）；**最后一条** `corrections[].why` 的原话以「纠正理由（原话）：…」同段保留（白名单里没有"纠正理由"这个字段，§1.2 只冻结了上表那 16 个）；`detail` 为空才用 `corrections[].why` 兜底 |
| `适用条件` | **最后一条** `corrections[].scope`（它还有 `target` 就附一行「适用对象」）；没有 `corrections` 才用 `qRef` |
| `包id` / `卡id` / `包版本` | 最后一条 `corrections[].target`（其次其它条）里第一个合法的选卡串（形状判据复用 `parseCardSel`，不另写一份） |
| 其它 | 不搬（尤其是 `student` 一类学生/家长标识，一个字段都不进草稿） |

> 公开仓那一侧（`.github\ISSUE_TEMPLATE\experience.yml`）的七个必填 id 与本节的映射，
> 由 `tests\neg-experience-draft.cjs` 的**跨模块对拍**钉住（表单的「版本」是聚合概念：
> 落到 `包版本` / `配方版本` / `工具版本` 三个字段上 —— 照字面做"七项 ⊆ 白名单"必假红）。

类型不是 `经验线索`、或既没有 `corrections[].why` 也没有 `detail` ⇒ exit 2（不拿 `question` 硬凑）。

### 14.3 隐私扫描（六类；命中即 exit 1 并点名"是哪一条、在哪个字段"）

| # | 形态 | 判定 |
|---|---|---|
| ① | 盘符 / 家目录（`X:\…` 形态、`Users\` 形态） | 红 |
| ② | 库内路径（`_收件箱` / `_原图` / `_录题` / `_备份-真源` / `_待确认`） | 红 |
| ③ | 任务号 `t-YYYYMMDD-HHmmss-xxxxxx` | 红 |
| ④ | 64 位十六进制（sha256 形态） | 红（唯一具名例外见 §14.4） |
| ⑤ | 孩子化名（`tests\repo-hygiene.cjs` 禁词表里那两个二字化名） | **替换**为「孩子A」/「孩子B」并报处数；原词**不在输出里复述** |
| ⑥ | 源记录里出现手写批注 / 聊天原文形态的**字段名** | 红（内容认不出来，但"源里存在这样一个字段"是确定信号） |

扫描面 = **组装结果的全部字符串叶子** + **源记录的字段名**；扫描后还会对"将要外发的那份文本"
再扫一遍（序列化/围栏不该引入新形态，引入了就 fail-closed 判红）。

**阴性对照**是硬要求：每一类都在 `tests\neg-experience-draft.cjs` 里被**故意塞进源**、真跑红过
（化名那一类真跑"替换 + 报处数 + 原词 0 残留"）。

### 14.4 唯一具名例外（白名单，不是通配豁免）

`合成案例` 的 `expected.json` 里，**逐个点名**的这两处 64 位十六进制是"合成案例自己那张
`input.svg` 的字节 sha256"——它随同批交付的 `input.svg` 一起走、可由它复算，**不是库内对象哈希**：

```
input.pageSha
expected.regions[].pageSha
```

其他任何位置（含案例文本里的其他字段、卡正文、任何白名单字段）出现 64 位十六进制都判红。
将来案例契约新增哈希字段，会在这里**判红并点名**，逼人回来显式决定"它算不算自证哈希"。

`--form cloud` 连这两处也剔除（替换成一句说明文字）：云外发版的"零哈希"因此是**字面事实**，
而不是"带一个我们自认为无害的哈希"。

### 14.5 两种形态（差别在"给谁看"）

| 形态 | 是什么 | 适合 |
|---|---|---|
| `local`（默认） | JSON，保留字段名与案例相对结构 | 本地留档 / 日后自己再加工 |
| `cloud` | 纯 Markdown | 贴给云端 AI / 公开提交（零本机路径、零哈希、零任务号） |

两者都必须在输出里打印"哪一份适合留档、哪一份适合外发"；两形态的**字段集合相同**，差别只在呈现。

### 14.6 `--json` 形状

```json
{ "ok": true, "code": 0, "cmd": "预览", "form": "local",
  "source": { "kind": "card", "sel": "family-a/shared-stem/shared-stem@1.0.2", "caseId": "shared-stem" },
  "fieldsFilled": ["方法正文", "…"], "fieldsOmitted": ["配方id", "…"], "omittedNotes": ["…"],
  "scan": { "hits": [], "exemptions": 3, "replacements": [{ "slot": 1, "to": "孩子A", "n": 2 }],
            "maskedHashes": 0, "caseHashPaths": [ … ] },
  "out": { "path": "…", "bytes": 1234 }, "draft": { "…只有白名单字段…" }, "text": "…将要外发的那份文本…" }
```

判红时 `ok=false / code=1`，`draft` 与 `text` **都不出现**（只给 `scan.hits`）。
`白名单 --json` 给 `{ ok, fields, excluded, scanRules, caseHashPaths, forms, assembly }`。

### 14.7 已知边界（写清楚，别假装没有）

1. **只读源**：除 `--out` 那一个文件外什么都不写（`预览` 一个字节都不写；判红时 `导出` 也不写）。
2. **不改用户库**：`--from-pending` 只读 `_待确认.json`，不加锁、不写回、不动 `数据\`。
3. **不做"内容级"识别**：判据是形态（正则）与字段名，**没有实体识别** —— 一段没写路径、没写名字的
   隐私叙述（例如"我们小区门口那家店的老板"）扫不出来，只能靠人看一眼预览再决定要不要分享。
4. **合成案例只收文本**：`input.svg` / `expected.json` 必须是有效 UTF-8，否则"原样字节"这句承诺
   无法成立 ⇒ exit 2 拒收（不是静默替换成 U+FFFD）；图片字节一律不进草稿。
5. **`--case` 收的是案例 id（一段）**，不是路径；案例目录必须在卡的 `cases[]` 里声明、目录名与
   `expected.json` 的 `caseId` 必须一致，否则 exit 2 并在原因里给出两侧的值 / 磁盘上未声明的目录。
6. **不代替人下结论**：草稿只是"可以先看的那一份"，分享与否由人决定（本工具不联网、不上传）。

> 回归锁：`tests\neg-experience-draft.cjs`（正例 / 从零组装 / 六类阴性对照 / exit 2 族 / 只读纪律）。
