# 配方规范（AI 方法层）

> 立：2026-10-27 ｜ 引擎：`src\tools\_配方.mjs`（唯一读取/校验入口）
> 本文的作用：把「AI 怎么把照片变成错题卡」这套方法**当资产管起来**，而不是留在个人习惯里。
>
> 一句话：**程序不带大脑，但带说明书和判卷标准。**

## 一、为什么要单独一层

数据层的每一件事都有机器兜底（原子写、台账、三道门禁、快照）。只有一件事没有：
**怎么让一个 AI 认出这是错题、判出错在哪、把题面转成印刷体。**

这件事不进程序，原因有三：

1. **它一定会变**——模型换、题目题型变、遇到新坑。写进程序就等于天天改程序。
2. **它不该联网**——程序承诺完全离线。AI 由用户自带，程序只负责给任务单、校验回来的结果。
3. **它是纯文本**——最适合被阅读、被审、被增量改进。

所以分成两层：

| 层 | 位置 | 变化频率 | 谁能改 |
|---|---|---|---|
| **内核** | `src\tools\`、`src\app\`、`src\shell\` | 低 | 开发者（走发布链路） |
| **配方** | `src\recipes\` | **高**（加反例即变） | 贡献者（走 PR） |

**内核不认识任何一道题、任何学科。** 这是可插拔的前提。

## 二、目录与文件职责

```
src\recipes\
├─ _core\                ← 跨学科铁律，所有配方自动带上
│   ├─ base.md           ← 转录/作答/答案来源/置信度 18 条
│   ├─ cause.md          ← 错因 K/L/S 16 类判据（唯一口径）
│   └─ provenance.md     ← 原图溯源：sourceImageSha256 必填
├─ _subject\             ← 学科补充，按 --subject 只加载一个
│   ├─ 数学.md 物理.md 化学.md 英语.md 语文.md
│   └─ 通用.md            ← 没有该学科文件时的兜底（会打印警告）
├─ _textbook\通用.md      ← 教材版本差异（默认不挂载，空着零开销）
├─ ingest-single\        ← 配方①：一题一张照片
└─ ingest-page\          ← 配方②：一张整页 → 多条记录
```

**每个配方目录固定五件套**（缺一件引擎会报错，不会静默降级）：

| 文件 | 给谁看 | 进提示词吗 | 缺了会怎样 |
|---|---|---|---|
| `meta.json` | 引擎 | — | 不算配方（目录被忽略） |
| `prompt.md` | **AI** | ✅ | 抛错 |
| `schema.json` | 引擎 | ❌（另有用途） | 抛错，无法校验 |
| `anti-patterns.md` | **AI**（兼给人） | ✅ | 警告：等于没有踩坑经验 |
| `checklist.md` | **人** | ❌ | 警告：抽查无依据 |
| `examples/<case>/expected.json` | 人 + 自检 | ❌ | 无法自检 |

### 🔴 一条最重要的分工

- **`anti-patterns.md` 是给 AI 看的**，会被拼进提示词 → 加反例直接改变 AI 行为
- **`checklist.md` 是给人看的**，不进提示词 → 加条目只改变人的抽查动作，不影响 AI

**别把这两件事写混。** 写反了的结果是：你以为改了 AI，其实只改了文档。

## 三、改配方的三条纪律

### 1. 改 `prompt.md` 正文 → 极慎重

正文是配方的核。**改错一句可能让整体变差**，而且很难察觉——因为输出仍然"看起来对"。

判断标准：只有当**同类错误在多个样本上重复出现**、且反例已经不足以纠正它时，才动正文。
动之前必须先跑一遍 `自检`，动之后再跑一遍，**用分数说话**。

### 2. 加 `anti-patterns.md` 反例 → 安全，随便加

这是本层的**主要进化方式**。一条反例 = 一次 patch。

格式固定三段（缺任何一段，后来人都看不懂它为什么存在）：

```
## A-NN 一句话标题

❌ 现象（贴真实输出，不要概括）
✅ 应该是（贴正确输出）
**为什么**（讲清后果，不是讲规范）
```

**"为什么"必须写后果，不能写规则。** 例：
- ❌「应该遵守 schema」← 这是规则，说了等于没说
- ✅「来源一旦造假，整套质量闸门就废了——因为闸门信的就是'来源可靠'」← 这是后果

### 3. 改 `schema.json` → 等于改契约，要同步三处

`schema.json`、`prompt.md` 的输出格式示例、`_配方.mjs` 里可能的推断逻辑（如按 `pageSummary` 识别整页配方）。

**三处不同步 = 契约漂移。** 这类漂移最坏的地方是它不报错，只是"部分记录被拒、部分通过"。

## 四、版本与指纹

- `meta.json` 的 `version` 手工递增（`主.次.修订`），并在 `changelog` 追加一条**说清改了什么、为什么**。
- **内容指纹**由引擎自动算：`node src\tools\_配方.mjs 指纹`
  它把实际拼进去的每一层文本算 sha256 前 12 位。**改任何一个字，指纹必变。**
- 任务单头部会写出指纹 → **事后能证明"这批卡是哪一版配方产出的"**。
- 也正因为如此，**指纹是质量对比的锚**：换了反例之后跑同一批样本，分数变好还是变差，有据可查。

## 五、用户带自己的 AI 时，怎么保证不踩我们踩过的坑

三个机制，缺一不可：

| 机制 | 作用 | 在哪 |
|---|---|---|
| **契约**（schema） | 结构不对直接拒收 | `校验` 命令 |
| **判据**（checklist） | 人按清单抽查高危信号 | 打印在任务单里 |
| **反例**（anti-patterns） | 把"具体怎么错的"喂给 AI | 拼进提示词 |
| **评分**（自检） | 客观回答"你的 AI 行不行" | `自检` 命令 |

关键认知：**我们后来不再踩这些坑，不是因为记住了，是因为有闸门在挡。**
所以让别人不踩的唯一办法，是把"记性"变成"闸门"。

## 六、发现新坑时的标准动作

```
① 留最小复现样本
   一张图 + 期望输出 + 实际输出（缺样本的坑无法验证修没修好）

② 判断能不能机检
   能  → 补 schema 约束（或给 _配方.mjs 加一条可计算判据）
   不能 → 写一条 anti-patterns.md（❌/✅/为什么）

③ 递增 meta.version + 写 changelog
④ 跑自检，确认分数没退
⑤ 提交 PR —— 用户拉新版本即受益，不用重装程序
```

**第 ② 步是要点**：能机检的就别只写文档。文档靠自觉，门禁靠机器。

## 七、已知边界（写清楚，别假装没有）

1. **配方只能约束输出，不能改程序行为。** 想让它"多一个按钮"属于改内核，另走发布链路。
2. **配方不含任何学生数据、不含 API Key、不联网。** 违反这条即拒绝合入。
3. **校验器是 JSON Schema 子集**，只支持 `type/required/properties/additionalProperties/enum/const/pattern/minLength/maxLength/minItems/maxItems/minimum/maximum/items`。
   用了别的关键字会**直接报错**（不静默放过）。需要新关键字就往 `SUPPORTED` 里加，别绕过。
4. **自检不是回归测试。** 它是给"换了自己的 AI"的用户打分的。样本少、图片不含真卷，分数只能看相对高低，不能当绝对质量证明。
5. **同一题多图、跨页题、答案在图上**这些形态，配方里只给了原则（`hasFigure`、逐空登记），
   落库时的硬校验在 `_作答门禁.mjs`，两边口径必须一致。

## 八、为什么不做"让用户自己编辑配方"

`_配方.mjs` 只读配方、**不提供写入命令**，这是刻意的：

配方是质量基础设施。用户随手改一句提示词，可能让**所有记录**的质量下滑，而他自己看不出来——
因为输出仍然"看起来对"。所以：

- **贡献者**：改配方 → 走 PR → 有人审 → 可回滚 ✅
- **终端用户**：只能升级版本，不能改内容 ✅

这个边界和"程序不带大脑"是同一条原则的两面。
