# 原图保全（内部契约）

> 立：2026-10-31（外部评审两路驱动的整改）
> 对应铁律（用户明示）：**数据方面原图是最重要、也是唯一不可复现的数据。它是核心。**

本文只写**不可从代码推断**的规则：什么算原图、身份怎么定、什么能删什么不能删、备份的分母是什么。
实现见 `src\tools\_原图.mjs`（保全库）与 `src\tools\_影像备份.mjs`（备份/镜像）。

---

## 一、三个身份，不能混

| 身份 | 是什么 | 怎么定 | 能不能删 |
|---|---|---|---|
| **原图** | 整页试卷/作业照片、导入原件、收件箱里的来源映射与人工判读 | sha256 | **永不删**。删 = 数据永久丢失 |
| **孤本派生** | 无法证明能原样重建的派生件（无 `box` 的卡片证据图、待办证据截屏、笔形样本、撤卡留档、组卷成品） | sha256 + 「不在可重建集合里」 | 按原图待遇保全 |
| **可重建派生** | `_crops\`、`tiles\`、`_work-*\`、`zzznew\` | 由原图 + 裁切参数唯一确定 | 可删，随时重算 |

### 「可重建」是一个**需要证明**的断言，不是看一个字段齐不齐

- **不许**因为卡片有 `box` 就把它的 `原卷截图.jpg` 降级为可重建。实测 442 张卡的
  `原卷截图.jpg` 与 `page` 整页**尺寸无一相同**——它其实是"整页 + 红框"裁出来的那一块，
  而源图版本、旋转、缩放、编码任一不同，重裁都得不到同一份字节。`boxOk()`
  只校验"是 4 个 0~1 的数"，它**不能证明可重建**。
- **不许**因为文件在 `组卷\` 目录里就宣布可重建。那是给人看的成品。
- 要降级，唯一可接受的证据是：**在不覆盖原证据的前提下真的重建一次，并核对结果等价**。

---

## 二、身份 = 内容哈希，路径只是提示

这不是理论洁癖，有两次实测：

1. 台账里同一张照片同时出现「收件箱原名」与「原卷库改名后」两套路径（sha 相同）。
   2026-10-31 那轮只认路径的判据在 256 张里漏判 4 张，用户当场复报"这些照片我们都处理过了呀"。
2. `_页码映射.json` 的 `en` 段有 7 条指向**根本不存在的**
   `九年级/英语/原卷/课课练9上-p{24,27,31,36,39,47,48}-src{77,80,84,89,92,100,101}.jpg`——
   真实字节还躺在收件箱里叫 `pNN-srcNN.jpg`，从未改名。

**所以：任何"这张图是不是同一张"的判断，必须比字节；拿路径字符串认亲一律视为缺陷。**

## 三、保全库：`数据\_原图\`

```
_原图\<sha256 前 2 位小写>\<sha256 小写>.<原扩展名>
_原图台账.json            （在库根，不在 _原图 里面）
_原图\_快照\<时间戳>.list
```

### 三条不变量（违反即报错退出，绝不"猜一个分支继续跑"）

1. **只增不改**：目标已存在但内容不同 ⇒ **报错停止，绝不覆盖**。
   这不是"哈希碰撞才可能发生"的边角情况：磁盘位损坏、同步盘回滚都会造成它。
2. **永不删除源文件**。`入库` 只复制。清理是另一件事，必须单独批准。
3. **落盘后逐字节复核**：写完立刻重读目标算 sha256，对不上就删掉目标并报错、保留源文件。
   （源文件可能在"算哈希"与"复制"之间被改名/覆盖，只有事后复核能发现。）

### 扩展名必须保留原格式

`a.png` 存成 `<sha>.png`，绝不改成 `.jpg`。改扩展名冒充转换 = 声称"保留了原件字节"而实际转码了。

### 幂等与续跑

重复入库同一个文件 = 什么都不做（返回 `exists`）。中断后直接重跑，不会重复占空间、
不会产生半截对象（先写 `.tmp` → fsync → rename）。**入库不需要事务日志**：对象先落稳、
台账后提交，中断最多留下可识别的未登记对象（`校验` 会以"孤儿"列出，不自动删）。

### 快照：只存清单，**不能替代字节备份**

因为不变量①，对象永不被改写 ⇒「某时刻的库」==「那一刻的 sha 清单」。
所以快照不复制字节，只写一份 40 KB 的清单，`--diff` 与**物理扫描**对照（不是与台账对照——
台账是元数据，删掉对象后台账照旧记着它）。

**但清单只能证明"丢了什么"，不能把字节变回来。** 真正的副本靠 `_影像备份\` + 离机镜像。
拿"有清单"当"有备份"是本项目明确禁止的推理。

## 四、备份：分母不由工具挑

判据一句话：**分母 = 全库扫描 − 显式声明的可重建集合**。

- 显式可重建集合只有一个地方定义（`_影像备份.mjs` 的 `REBUILDABLE_RE`）：`_crops`、`tiles`、
  `组卷`、`_work-*`、`zzznew`。**新目录默认进分母**——"没被规则命中"不等于"不用备份"。
- `_原图\` 里的对象**按内容全收，不看扩展名**（来源映射 CSV、人工判读 MD 都在里面）。
- 分母必须写进输出。**"我选中的文件都备份好了"这句话永远为真，因此毫无价值。**
- 校验必须**读字节算哈希**，不是比 size、不是比 mtime。
  实测：把一份镜像副本改成"同字节数、不同内容"，只比 size 的判据必然判它"一致"。
- 镜像里源已删除的陈旧件：**只报告，不自动删**（删不删是人决定）。
- 覆盖率不进 100% ⇒ 退出码非 0，**所有模式一套**（`--status` 也要判红，不留"只看不判"的口子）。

## 五、改这个体系时最容易犯的错

| 症状 | 根因 |
|---|---|
| 门禁全绿但原图丢了 | 判据的分母是"我挑的文件"，或校验比的是 size/mtime |
| "删掉对象后工具仍报正常" | 拿台账当"库里现在有什么"，而台账不会因为文件消失而变 |
| 内容被改坏却查不出 | 用 `existing.size === src.size` 判"已存在" |
| 溯源断了但卡片还能显示 | 只更新了卡片引用的路径字段，没同步身份字段（或反过来） |
| 以为备份好了 | 同盘副本当备份；或把快照清单当备份 |

## 六、怎么自己验

```powershell
$env:CTB_DATA='<库根>'
node src\tools\_原图.mjs 校验                          # 逐字节核对全部对象，任一异常 exit 1
node src\tools\_原图.mjs 快照 --diff <最新清单>          # 有没有对象"非正常消失"
node src\tools\_影像备份.mjs --status                   # 分母 / 已备份 / 缺失 / 镜像陈旧件
node tests\neg-orig-store.cjs                          # 保全库的 8 组阴性对照（35 断言）
node tests\neg-image-backup-coverage.cjs               # 备份分母的 37 条断言
```

> 上面两条阴性对照是**这条链唯一可信的证明**：它们分别证明了
> "同长度损坏会报红""删掉对象会报红""拒绝覆盖""删除后能回到绿（判据不是恒红）"
> "分母由扫描决定而不是写死"。门禁退出 0 只说明"没触发检查"，不说明"数据安全"。
