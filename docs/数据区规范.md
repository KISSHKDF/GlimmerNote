# 数据区规范（库根宪法）

> 立：2026-11-06 ｜ 触发：用户质询「两个小孩，一个文件夹叫 `九年级`，另一个叫 `七年级-<小名>`，难道就这么随意的吗？」
> 本文是**规范性文件**：库根（`数据\`）里**放什么、叫什么、谁写、怎么判违规**，全在这里写死。
> - 机器判据（唯一实现）：`node src\tools\_数据区门禁.mjs`；阴性对照 `node tests\neg-data-area-rules.mjs`（证明它真会红）。
> - 用户向说明只给指针，不重述本文（AGENTS.md 红线 8「一份事实只住一个家」）。
> - 本文不写"当前状态"类会过期的内容（AGENTS.md 红线 9）；历史进 `CHANGELOG.md`。
> - **本文不出现真实化名**：公开仓的隐私红线由 `tests\repo-hygiene.cjs` 机检（tracked 文件禁词 0 命中），
>   本文一律用 `<小名>` / `学生甲` / `学生乙` 这类占位。举例里的目录名不是本机实况，是**形态示范**。

---

## 一、八条第一原理

规则不是拍脑袋列的，是从这八条推出来的。**任何新规则必须先能挂到其中一条上**，否则不加。

| # | 原理 | 一句话 | 它管住了什么 |
|---|---|---|---|
| **P1** | 单一真源 | 一个事实只存一处，其余都是它的投影 | `student` 字段是真源，目录名只是给人看的投影 |
| **P2** | 投影可推导 | 凡是人能看见的名字，必须能由真源机械推出 | 目录名与 `student` 字段必须逐字相等 |
| **P3** | 可变属性不进身份 | 会变的、可多值的，不准进名字 | 年级会升级、学科是题的属性 ⇒ 都不得进目录名 |
| **P4** | 闭集 | 每一层允许有什么是**枚举**出来的，表外即违规 | 从机制上堵死"再来一个 `_probe`" |
| **P5** | 五类职责分离 | 真源 / 派生 / 过程 / 备份 / 产物，各有唯一落点 | 每类文件的生命周期不同，混住就没法清理 |
| **P6** | 过程件零留存 | 跑完就该没的东西，一个字节都不进库 | 探针、缓存、预览、临时件 |
| **P7** | 可机械验证 | 没有判据的规则等于没有规则 | 每条规则都有对应检查，门禁能红能绿 |
| **P8** | 迁移可回滚 | 先备份、留台账、可逐字节对账 | 任何搬迁都可撤销、可验证 |

**P1 的双向义务（2026-11-06 补）**：规范与实现冲突时，**默认改规范去跟随"唯一实现"**，
而不是让实现去迁就一句想当然的话 —— 除非能证明那个实现是错的。N12 就是这么来的。

## 二、身份与命名（N 系列）

### N1　学生目录名 = `student` 字段（逐字符相等）

学生库目录名**必须逐字等于**该目录内 `_索引.json` 的 `student` 字段。

- **依据**：P1 + P2。程序全程按 `student` 字段认人（查重、分组、组卷按学生过滤都读它），目录名不参与任何判据。
  两者不一致时，"人看到的目录名"与"程序用的身份"是两个答案 —— 这正是
  「目录名叫 `九年级`、里面住的其实是另一个小名」能长期存在、且**谁都没报错**的根因。
- **反例**：`九年级\`、`七年级-<小名>\`、`<小名>-数学\`、`<小名> 9年级\`。

### N2　`student` 命名集（小名）

`student` 字段与目录名都不得包含：

| # | 类别 | 字面集（门禁按此实现，改词表 = 改本文 + 改码 + 加阴性对照） |
|---|---|---|
| 1 | 年级/学段词 | 数字 `一二三四五六七八九` + `年级`（`七年级`／`9年级`）及其缩写 `七上`／`八下`／`*年级上册`／`*年级下册`；另加 `小学` `初中` `高中` `初[一二三]` `高[一二三]` |
| 2 | 学科词 | 闭集：`数学` `语文` `英语` `物理` `化学` `生物` `历史` `地理` `政治` |
| 3 | 时间限定词 | `上`/`下`+`册`、`第*周`、`第*单元`、`*月份`、`*月*日`、`国庆`、`寒假`、`暑假`、`期中`、`期末`、`月考`、`五一`、`十一`、`元旦`、`开学`、`假期`、`[春秋]季`、`[上下]学期`、`\d{4}年` |
| 4 | 日期形态 | `\d{4}[-./]\d{1,2}([-./]\d{1,2})?`（如 `2026-10-06`） |
| 5 | 空白符 | 半角与全角空格、制表符 |
| 6 | 分隔符 | `-` `_` `.` `/` `\` |
| 7 | Windows 非法字符 | `: * ? " < > \|` |

长度 ≤ 20 字符。

- **依据**：P3。年级是**学年属性**（今年七年级、明年八年级）—— 把年级写进目录名，等于埋一个
  "每年必须改名、改名就断引用"的定时炸弹。学科是**题**的属性，不是**人**的属性（`_建学生.mjs` 头注已讲透）。
- **正例**：`学生甲`、`学生乙`。小名即可，不必也不许是真名（隐私红线）。

### N3　保留名

小名不得取：`组卷`（见 C 系列保留名）、任何一个以 `_` 或 `.` 开头的名字、以及 Windows 设备名
（`CON`/`PRN`/`AUX`/`NUL`/`COM1`…`COM9`/`LPT1`…`LPT9`）。

### N4　学科目录名是闭集

`<库根>\<小名>\<学科>\` 的 `<学科>` ∈ `{数学, 语文, 英语, 物理, 化学, 生物, 历史, 地理, 政治}`，
且必须**恰好是该学生 `_索引.json` 的 `subjects` 键**（多一个 = 有卡无册；少一个 = 有册无卡）。

- **依据**：P4 + P2。学科名同时是 `subjects` 的键、是卡号前缀的来源、是 `_录题入库.mjs` 的落点判据。

### N5　卡目录名

`<前缀><4 位十进制序号>-<描述>`，例：`<小名>\数学\M0142-煮面条最少时间未作答\`。

| 项 | 规则 |
|---|---|
| 前缀 | 按学科唯一映射：数学`M` 语文`Y` 英语`E` 物理`P` 化学`C` 生物`B` 历史`H` 地理`G` 政治`Z` |
| 序号 | 4 位零填充，在**该学生该学科**内唯一、**只增不复用**（复用会撞历史台账） |
| 描述 | 非空、≤ **40** 字符、不含 Windows 非法字符、不含换行、不以空格或 `.` 结尾 |

- **40 这个数怎么来的（诚实写明）**：它是**防退化**的上限，不是审美。实测全库最长样本 36 字符
  （英语卡的描述天生偏长，如 `课文词块误写(oneself、the position、all the)`）。
  2026-11-06 立规范时初稿写 24，实测会逼着改 5 张**已入库**的卡名，并连带改
  `_原卷台账.json` / `_配图台账.json` / `_待确认.json` 等 4 份台账里的路径 ——
  代价是断引用风险，收益只是"短一点"。**判据存在的意义是防退化，不是逼人改历史**，故定为 40。
- **依据**：P2。卡目录名与台账的 `cardDir` 逐字对应，是"这道题在哪"的唯一定位串。

### N6　台账文件名

库级台账一律 `_` + 中文短语 + `.json` / `.md`，**住在库根**，不得下沉进学生目录。

- **依据**：P5。台账是跨学生的登记册（`_组卷台账.json` 记批次、`_原卷台账.json` 记整页、`_待确认.json` 记待裁量项），
  下沉到学生目录就变成"每个学生一本"，跨学生查询立刻失效。

### N7　保留目录名

程序保留目录一律 `_` 开头。**学生目录与学科目录不得以 `_` 或 `.` 开头**（生成器按此跳过，见 `生成状态.mjs` 的口径）。

### N8　通用文件名卫生

库根任何条目：不含 Windows 非法字符、不以空格或 `.` 结尾、不是 `.` / `..`。

### N9　唯一例外

`.git\` 与 `.gitignore` —— 库自身是 git 仓库（文本真源可回溯），这两个是版本控制的载体，不算数据条目。

### N10　原卷落点

整页原卷（`_原卷台账.json` 的 `page` 所指的那些扫描件）一律住在 `<库根>\<小名>\` **之下**，两种合法形态：

| 形态 | 何时用 |
|---|---|
| `<小名>\原卷\<批次>\` | 跨学科合卷，或批次尚未归到某一科 |
| `<小名>\<学科>\原卷\<批次>\` | 已知学科的整页 |

**禁止**把 `page` 指到库根顶层的无前缀目录。判据不是审美，是**能不能显示**：前端静态服务
（`_服务端.mjs`）只放行「路径段不以 `_` 开头」的位置，外加 `_原图\` / `_收件箱\` 两个例外；
`page` 指向别处 ⇒ 灯箱与「回原卷」直接 403。

- **机器判据已存在**：`_原卷台账.mjs 门禁` 的"库外 page"检查。本规范不另实现一份（P1：一份事实只住一个家）。

### N11　学科目录里允许有什么（闭集）

`<库根>\<小名>\<学科>\` 下**只允许**：

| # | 形态 | 是什么 |
|---|---|---|
| ① | `<前缀><4位>-<描述>\` | 卡目录（N5） |
| ② | `原卷\` | 整页原卷（N10）；其内可含 `_crops\`、`tiles\`（可重建的中间产物） |
| ③ | `待办证据\`、`_待确认证据-<YYYYMMDD>\` | 待办证据图暂存（"回原卷"链路要显示它） |
| ④ | `*.md` | 报告/记录件（给人看的产物，如批改报告） |
| ⑤ | `_` 或 `.` 开头的条目 | 程序件（扫描器一律跳过；`_备份-真源\` 属此类，见 N12） |

其余即违规。

**`<小名>\` 这一层允许什么**（与 N11 对称的闭集）：

| # | 形态 | 是什么 |
|---|---|---|
| ① | `_索引.json` | 该学生唯一一份索引（F1 真源） |
| ② | `<学科>\` | N4 闭集里的学科目录 |
| ③ | `原卷\` | N10 允许的**跨学科**原卷形态 |
| ④ | `_` 或 `.` 开头的条目 | 程序件（含 `_备份-真源\`，见 N12） |

**不放 `*.md` 报告件** —— 报告件只在学科目录层（N11④）。学生层是"身份 + 学科"的骨架，
塞进随笔文件会让"这个学生有哪几科"变得不可枚举（`findIndexes` 那类递归扫描也会多绕路）。

- **依据**：P4。判据不是洁癖：`生成状态.mjs` / `_录题入库.mjs` 等按"`_`/`.` 开头一律跳过"的口径递归找
  `_索引.json`，学科目录里塞进别的东西，"这是卡还是辅助目录"就只能靠猜。
- **不许拿"反正没人读"当理由往这儿放东西**：库是要能被人（和下一轮迁移）读懂的结构。

### N12　`_备份-真源\` 可以出现在任何层级

`_备份-真源\` 是 `_安全写.mjs` 的**滚动备份落点，写在被备份文件旁边**（`backupJson()`），
所以它既出现在库根，也出现在 `<小名>\` 与 `<小名>\<学科>\` 下。**任何层级都合法**，不是"下沉违规"。
同样地，N11 的 ⑤ 覆盖它。

- **依据**：P1 —— 备份落点由**唯一实现**决定；规范跟随实现（见 §一 的双向义务）。
  想让它集中到库根，得先改 `_安全写.mjs` 并复验 `_快照.mjs` / `tests\run.mjs` 的备份轮转放行判据；
  那是另一件事，不在"命名规范"的射程内。

## 三、库根顶层闭集（C 系列）

**规则本体**：库根顶层的每一个条目，**必须**在下表之内。表外的任何东西 = 违规（P4）。
新增一类 = 改本文 + 改门禁 + 加阴性对照，三件一起做，缺一不算。

### 3.1　无前缀顶层 = 用户能看见的实体（只有两类）

| 条目 | 类别 | 是什么 | 谁写 | 入 git | 进 `_影像备份` 分母 |
|---|---|---|---|---|---|
| `<小名>\` | **S 学生库** | 孩子的题库（真源） | `_建学生.mjs` / `_录题入库.mjs` / `_标记复习.mjs` | ✔ | ✔（卡图） |
| `组卷\` | **O 产物** | 印出来的成品卷（PDF） | 组卷链路 | ✘（可重印） | ✘（`REBUILDABLE_RE`） |

> 为什么只有 `组卷` 是个无前缀的保留名：它是**给人看的成品**，要和学生的东西一样能被一眼找到；
> 其余程序件一律 `_` 前缀，前端静态服务默认不下发（`_服务端.mjs` 的 `LIB_DIR_ALLOW`）。

### 3.2　`_` 前缀顶层 = 程序保留区（枚举在册）

| 条目 | 类别 | 是什么 | 生命周期 | 入 git |
|---|---|---|---|---|
| `_原图\` | **I 影像真源** | 内容寻址保全库 `<桶>\<sha256>.<ext>`，只增不改。**已知一处差额**：`_原图\` 下的文件数会比 `_原图台账.json` 的对象数**多 1** —— 那一个是 `_快照\20261031-213815.list`（内部快照清单，不是对象；`_原图.mjs` 与 `_影像备份.mjs` 都显式排除它）。**别把它报成"台账漏登记"** | 永久 | ✘（字节仓库，靠备份） |
| `_影像备份\` | **B 备份** | 按路径镜像的库内副本（`原件\<相对路径>`） | 随库演进 | ✘ |
| `_备份-真源\` | **B 备份** | 文本真源的滚动快照（**也可出现在下层**，见 N12） | 滚动 | ✔ |
| `_收件箱\` | **W 工作区** | 原始照片投递区；批次目录 `<日期>-<小名>-<学科>-<描述>` | 原件永久留存（"一张都没删"） | ✔ |
| `_录题\` | **W 工作区** | 录题任务记录 `<taskId>.json`（用户数据） | 永久 | ✔ |
| `_盲解\` | **W 工作区** | 盲解清稿（双路复算的输入） | 永久 | ✔ |
| `_撤卡留档\` | **W 工作区** | 撤销/误建的卡留档 | 永久 | ✔ |
| `_笔形\` | **I 影像真源** | 笔迹样本（判"哪个字是谁写的"的依据，`_笔形台账.json` 的 `items[*].sample` 指向它） | 永久 | ✔ |
| `_工具\` | **W 工作区** | 库内脚本（`裁图.ps1` / `_带网格.ps1` 等） | 随库走 | ✔ |

### 3.3　库根台账文件（枚举在册）

`_组卷台账.json`、`_配图台账.json`、`_原卷台账.json`、`_原图台账.json`、`_盲解双路.json`、
`_笔形台账.json`、`_页码映射.json`、`_待确认.json`、`_待办欠账-派发.json`、
`_状态.json`（派生）、`_复习队列.md`（派生）、`_待确认清单.md`（派生）、`_词表.md`、
`首页.html`（派生看板，`_体检.mjs` 读它、`_服务端.mjs` 把 `/` 指给它）、`先看这里.txt`

### 3.4　明令禁止的东西（三个作用域，别混）

**① 库根顶层**：不得出现任何未列入 3.1 / 3.2 / 3.3 的条目（P4 闭集）。

**② 库内任何位置**（不限顶层）：不得出现
`*.bak-*`、`*.bak`、`*.old`、`*.orig`、`*.tmp-*`、`_probe\`、`_tmp*\`、`_快照\`。
备份件只有两个合法去处：`_备份-真源\`（库内）或库外。

**③ 只在特定位置合法的**：`tiles\`、`_crops\` 只能出现在卡目录/原卷目录**内部**
（它们是可重建的中间产物，见 `_影像备份.mjs` 的 `REBUILDABLE_RE`）；出现在库根顶层即违规。

**豁免（穷举，各有理由）**：

| 位置 | 为什么豁免 |
|---|---|
| `_备份-真源\` 内部（**任何层级**） | 它本身就是"文本真源的滚动快照"区，文件名带 `.bak-` 是历史留存；落点由 `_安全写.mjs` 的 `backupJson()` 决定（N12） |
| `_影像备份\` 内部 | 同上；且 `_影像备份.mjs` 在内容变化时会就地留 `<同名>.bak`（覆盖前保底） |
| `_原图\_快照\` | 内容寻址库的**内部快照清单**（只记录"某时刻有哪些 sha"），`_原图.mjs` 与 `_影像备份.mjs` 都显式把它排除在扫描与备份分母之外。**这是 `_快照\` 唯一的合法位置** |

- **依据**：P5 + P6。过程件的唯一合法落点是 `%LOCALAPPDATA%\拾光小册\proc\`（`_过程目录.mjs`），删掉它永远安全。

**已知边界（诚实写明）**：
- 本门禁管"名字形态与目录关系"，**不管"内容是否该留"**。一个合规命名的文件也可能毫无价值 ——
  那属于内容审计（`_体检.mjs` / `_原图.mjs 校验`），不是本文的判据。
- ② 的名字表是**穷举**的。要新增一种残渣形态 = 改本文 + 改门禁 + 加阴性对照。
- Win32 上造不出含 `?`/`*` 的目录（当场 EINVAL）⇒ G5 的"非法字符"子判据在本机**没有阴性对照**（判据保留）。

## 四、索引形态（F 系列）

### F1　一个学生 = 恰好一份 `_索引.json`

位置 `<库根>\<小名>\_索引.json`，形态：

```json
{ "student": "<小名>", "grade": "七年级", "subjects": { "数学": { "items": [] } }, "note": "", "updatedAt": "" }
```

**禁止**按学科拆成多份（`<小名>\数学\_索引.json` + `<小名>\英语\_索引.json` + …）。

- **依据**：P1。拆成多份就是"两份并列真源"：同一学生的复习状态散在多处，跨学科统计要先合并，
  而 `_录题入库.mjs` 的 `findTarget()` 在发现同一学生多份索引时会**直接拒收**并打印"请先合并成一个"。
  正典由 `_建学生.mjs` 定义（它建的永远是学生级一份索引）。

### F2　卡目录位置

`<库根>\<小名>\<学科>\<卡目录>\`，卡目录四件套：`题干.html` / `错题记录.md` / `原卷截图.jpg` / `_裁图记录.json`。
学科目录里除卡目录之外允许什么，见 **N11**。

### F3　写入归属

索引只由工具写；其中 `answerSlots` / `answerMode` **只能**由 `_作答门禁.mjs` 写入（既有红线，手工改不算数）。

### F4　派生物

`_状态.json`、`_复习队列.md`、`_待确认清单.md`、`首页.html` 是派生物：可随时重算、**不是真源**。
不要手工编辑；任何"逐字节对账"都要把它们单列（重算必然改字节，且 `_状态.json` 带 `generatedAt` 自证生产者）。

## 五、写入纪律（W 系列）

- **W1**　库根一切写入走 `_安全写.mjs`（原子写 + 跨进程库锁）。
- **W2**　过程件走 `_过程目录.mjs`，**不得**落库（P6）。
- **W3**　备份件落 `_备份-真源\` 或库外；**不得**在库里留 `.bak` / `.tmp` / `.old` 残渣。
- **W4**　新建学生只走 `_建学生.mjs` —— 目录名由它按 N1 产生，不得手工 `mkdir`。
- **W5**　库根路径由 `_库根.mjs` 的 `libraryRoot()` 解析（`CTB_DATA` > `<运行区>\..\数据` > …），
  任何工具不许自己拼库根，更不许写死盘符（`tests\portability.cjs` 会拦）。
- **W6**　**改盘别改格式**：搬迁/改写工具重写已有的库内文件时，必须**沿用该文件自己的缩进与换行**
  （从原文量出来，别用 `writeJsonAtomic` 的默认值）。实测教训：`_原卷台账.mjs` 与 `_原图.mjs`
  刻意用 `{ indent: 1 }` 写它们各自的台账，用默认 indent=2 重写会把**每一行**都改掉
  （纯路径改写变成 +41.6KB / +30.1KB 的全文件重排），既污染 diff 又让"字节守恒"对账失真。

## 六、门禁（G 系列）

```powershell
node src\tools\_数据区门禁.mjs                 # 对着当前库跑；全绿 exit 0，有违规 exit 2，入参错 exit 3
node src\tools\_数据区门禁.mjs --data <库根>    # 显式指定库（压过继承的 CTB_DATA）
node src\tools\_数据区门禁.mjs --json           # 机器可读信封
node tests\neg-data-area-rules.mjs             # 阴性对照：证明这些判据真会红
```

判据 ↔ 规则对照：

| 判据 | 规则 | 判红条件 |
|---|---|---|
| G1 | N1 | 学生目录名 ≠ 该目录 `student` 字段 |
| G2 | N2 | `student`/目录名含年级词、学科词、时间词、日期、空白或分隔符；超 20 字符 |
| G3 | N3 | 小名是保留名或 Windows 设备名 |
| G4 | N4 + N12 | 学科目录与 `subjects` 键不对应；学科名不在闭集内；**学生目录里出现白名单之外的条目**（白名单 = `_索引.json` + N4 学科目录 + `原卷\` + 任意 `_`/`.` 开头条目，含 `_备份-真源\`）。**学生目录层不允许 `*.md`**（报告件只在学科目录层，N11④） |
| G5 | N5 + N11 | 卡目录名不合 `<前缀><4位>-<描述>`（形态判据**只对 `^[A-Z]\d{4}` 开头的目录名生效**）；前缀与学科不符；同学生同学科内重号；**学科目录里出现 N11 之外的条目** |
| G6 | C3.1/3.2/3.3 | 库根顶层出现未登记条目（P4 闭集） |
| G7 | C3.4 | 库内任何位置出现 ② 的残渣名；`tiles\`/`_crops\` 越位（见 ③）。豁免只有三处（见 §3.4） |
| G8 | F1 | 同一学生出现多份 `_索引.json` |
| G9 | N6 | 库级台账下沉进学生目录 |
| G10 | N10 | 原卷落点 —— **见 `_原卷台账.mjs 门禁` 的"库外 page"检查**，本工具不重复实现（P1） |

门禁必须**能红**：只测正例的检查是恒真的，等于没测 —— 所以 `tests\neg-data-area-rules.mjs`
在合成库上逐条制造违规并断言每条都被判红（阴性对照），另加一组合法库断言全绿（防假阳）；
还要有一条**自证**：临时把某条判据改成永假，阴性对照必须失败（证明判据本身是活的）。

**作用域（诚实写明边界）**：本门禁管的是**用户的真库**（配置的库根）与**迁移验收**。
`fixtures\` 下由 `make-fixture-lib.mjs` 造的合成库**不受本门禁约束** —— 那些库是**故意**造成畸形形态的
（例如"同一学生拆两份学科索引"），用来证明工具链**容错读旧形态**。门禁不得接进 `tests\run.mjs` 去判它们，
否则等于要求工具链放弃对旧库的兼容。

## 七、违规与处置

| 违规 | 处置 |
|---|---|
| 学生目录名不符（G1/G2） | 改名到 `student` 字段值，并同步改写台账里以该目录为前缀的**路径字段**（只改路径，不改溯源叙述；见 §七.1） |
| 小名本身不合规（G2/G3） | 先改 `_索引.json` 的 `student`，再改目录名（顺序不能反：门禁按字段判目录名） |
| 一学生多份索引（G8） | 合并成学生级一份；合并前后**逐学科 items 条数必须相等**，并重跑四道卡门禁 |
| 学科目录/册不对应（G4） | 有卡无册 ⇒ 补进 `subjects`；有册无卡 ⇒ 从 `subjects` 摘掉（不得留空壳键） |
| 库根未登记条目（G6） | 三选一：① 它是真源 ⇒ 改本文登记 + 改门禁；② 它是过程件 ⇒ 移 `proc\` 或删；③ 它是备份 ⇒ 移 `_备份-真源\` |
| 库内残渣（G7） | 删，或移 `_备份-真源\`（若还想留它的字节）；**不删就用搬的**，这样"字节守恒对账"不会被残渣豁免搅浑 |
| 学科目录多出条目（G4/G5） | 卡 ⇒ 按 N5 改；辅助目录/报告 ⇒ 改本文登记（N11）；其余 ⇒ 移走 |
| 台账下沉（G9） | 移回库根，并改引用它的工具 |

### 七.1　路径改写的判据（搬迁/改名时唯一允许的做法）

**只改「旧值以 `<旧顶层段>/` 开头」的字符串值与对象键**；必须**带分隔符**判前缀。

- 为什么必须带分隔符：初版判据里多了一条"整串相等"，于是 `_索引.json` 的 **`grade` 字段**
  （值恰好是 `九年级`）被当成路径改成了小名 —— 一个非路径字段被静默改坏。
  普查实测：没有任何需要改写的路径值是"光秃秃一个段名"。
- **不改**叙述与溯源字段（`source` / `note` / `detail` / `evidenceFix` / `origFix` / `answer` …）——
  那是历史留痕（AGENTS.md 红线 6「不改写历史」）。这些字段的值从**不以**旧段名开头，所以锚定判据自动跳过它们。
- **例外（必须改）**：`_原图台账.json` 的 `objects[*].sources[]`。它不是叙述，是 `_原图寻址.mjs`
  的 `pathShas()` **反查表的键来源**；不改它，那些"盘上已不在、只能靠影像备份按同路径兜底"的
  `page` 就永远解析不到。**这条例外要单独声明**，不要假装它属于"路径字段"的默认集合。
  它的正确性判据很硬：**每条新值必须 === 新前缀 + 旧值去掉旧前缀后的原样余部**（逐字符）。
  2026-11-06 实测：846/846 全部是纯前缀替换、`sources` 条数漂移 0 ⇒ provenance 的"指向"没被改坏。
- **不改** `_备份-真源\` 下的任何快照 —— 备份是冻结证据，改了它就不是备份了。
- **改完必须独立复核**：逐文件把"搬迁前备份"与"现在"对拍，把每一处变化分类成
  「合法（旧值/旧键以旧段开头）」或「可疑」；**可疑必须为 0** 才算过。
