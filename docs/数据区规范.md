# 数据区规范（库根宪法）

> 立：2026-11-06 ｜ 触发：用户质询「两个小孩，一个文件夹叫 `九年级`，另一个叫 `七年级-<小名>`，难道就这么随意的吗？」
> 本文是**规范性文件**：库根（`数据\`）里**放什么、叫什么、谁写、怎么判违规**，全在这里写死。
> - 机器判据（唯一实现）：`node src\tools\_数据区门禁.mjs`；阴性对照 `node tests\neg-data-area-rules.mjs`（证明它真会红）。
> - 用户向说明只给指针，不重述本文（AGENTS.md 红线 8「一份事实只住一个家」）。
> - 本文不写"当前状态"类会过期的内容（AGENTS.md 红线 9）；历史进 `CHANGELOG.md`。
> - **本文不出现真实化名**：公开仓的隐私红线由 `tests\repo-hygiene.cjs` 机检（tracked 文件禁词 0 命中），
>   本文一律用 `<小名>` / `学生甲` / `学生乙` 这类占位。举例里的目录名不是本机实况，是**形态示范**。

## 一、八条第一原理

规则不是拍脑袋列的，是从这八条推出来的。**任何新规则必须先能挂到其中一条上**，否则不加。

| # | 原理 | 一句话 | 它管住了什么 |
|---|---|---|---|
| **P1** | 单一真源 | 一个事实只存一处，其余都是它的投影 | `student` 字段是真源，目录名只是给人看的投影 |
| **P2** | 投影可推导 | 凡是人能看见的名字，必须能由真源机械推出 | 目录名与 `student` 字段必须逐字相等 |
| **P3** | 可变属性不进身份 | 会变的、可多值的，不准进名字 | 年级会升级、学科是题的属性 ⇒ 都不得进目录名 |
| **P4** | 闭集 | 每一层允许有什么是**枚举**出来的，表外即违规 | 从机制上堵死"再来一个 `_probe`" |
| **P5** | 五类职责分离 | 真源 / 派生 / 过程 / 备份 / 产物，各有唯一落点 | 每类文件的生命周期不同，混住就没法清理 |
| **P6** | 过程件零留存 | 跑完就该没的东西，一个字节都不进库 | 探针、缓存、预览、临时件 |
| **P7** | 可机械验证 | 没有判据的规则等于没有规则 | 每条规则都有对应检查，门禁能红能绿 |
| **P8** | 迁移可回滚 | 先备份、留台账、可逐字节对账 | 任何搬迁都可撤销、可验证 |
| **P9** | **一孩一库、库间零特例** | 一个孩子一套数据；**规则只有一套，对每个孩子逐字相同地执行** | 禁止"老大这样、老二那样"；规则没盖到的地方必须补规则，不许默认放着 |
| **P10** | **一个字节一个家** | 同一个字节不许多处存放；**只有原图**允许第二个家 | 用户 2026-11-06：「数据不要太冗余……除了原图，同意你有一个备份，其它东西不要再有冗余了」 |

**P9 是用户 2026-11-06 的裁定，也是本文的立法理由**：

> 「一个孩子一套数据，两个孩子两套数据，但这两套数据应该是同一套规则，完全复用的。」

它管住三件事：

1. **数据按孩子分**（`<库根>\<小名>\` 一人一棵树），但**规则不分人** —— 不许出现
   "甲用日期当批次名、乙用另一种"这类只在一个人身上生效的约定；
2. **规则要盖满**：某处**没有规则** ≠ 自由。没有规则就意味着"没人管"，实际结果是两种写法并存。
   发现"规则没盖到的地方"必须补规则（本轮的 `_撤卡留档\`、`_笔形\`、`_收件箱\` 描述段就是这么补出来的）；
3. **机器要能查**：见 **G11 跨学生同构** —— 把每个孩子的库按类型抽象，**必答项必须同构**，
   再逐条核对"跨学生的共用命名规则"是否对所有人都成立。

**注意"同构"不等于"长得一样"**：学科集合、条目是否存在（原卷/待办证据/报告件/程序件）本来就因人因科而异，
那是**内容**差异，不是规则差异。G11 查的是"同一个位置上的东西，符不符合同一条规则"。

**P10「一个字节一个家」的口径（用户 2026-11-06 裁定，写死如下）**

- **原图 = 整页扫描 + 导入原件** —— 用户提供的**唯一材料**，用他的话说"这是一切的根源"。
  ⇒ 原图**恰好允许两个家**：

  | 家 | 在哪 | 为什么是它 |
  |---|---|---|
  | **工作家** | 活路径（`<小名>\<学科>\原卷\…`、`_收件箱\…`） | 程序与人工**直接读它**（`page` / `import`、裁图、灯箱）。动它就要动整条工具链，收益不抵风险 |
  | **保全家** | `_原图\<桶>\<sha>.<ext>`（内容寻址） | 改名、误删都兜得住（实测救回 452 张卡）。**它就是"那一份备份"** |

- **其它一切影像**（卡片裁图、待办证据、笔形样本、撤卡留档、组卷成品）⇒ **只允许一个家**。
  程序确实需要的，**必须登记在册、遵守命名规则**（"不能没有规则地到处乱放"）；不需要的按 §七 处置。
  **它们没有备份** —— 这是用户明示的取舍。
- **推论**：`_影像备份\`（按**路径**镜像的一层）既是原图的**第 3 个家**，又是"其它影像"的备份
  ⇒ 按 P10 属冗余，**退休中**（测量与影响面见 `_整改台账.md` R-1）。

**P1 的双向义务（2026-11-06 补）**：规范与实现冲突时，**默认改规范去跟随"唯一实现"**，
而不是让实现去迁就一句想当然的话 —— 除非能证明那个实现是错的。N12 就是这么来的。

## 二、身份与命名（N 系列）

### N1　学生目录名 = `student` 字段（逐字符相等）

学生库目录名**必须逐字等于**该目录内 `_索引.json` 的 `student` 字段。

- **依据**：P1 + P2。程序全程按 `student` 字段认人（查重、分组、组卷按学生过滤都读它），目录名不参与任何判据。
  两者不一致时，"人看到的目录名"与"程序用的身份"是两个答案 —— 这正是
  「目录名叫 `九年级`、里面住的其实是另一个小名」能长期存在、且**谁都没报错**的根因。
- **反例**：`九年级\`、`七年级-<小名>\`、`<小名>-数学\`、`<小名> 9年级\`。

### N2　`student` 命名集（小名）

`student` 字段与目录名都不得包含：

| # | 类别 | 字面集（门禁按此实现，改词表 = 改本文 + 改码 + 加阴性对照） |
|---|---|---|
| 1 | 年级/学段词 | 数字 `一二三四五六七八九` + `年级`（`七年级`／`9年级`）及其缩写 `七上`／`八下`／`*年级上册`／`*年级下册`；另加 `小学` `初中` `高中` `初[一二三]` `高[一二三]` |
| 2 | 学科词 | 闭集：`数学` `语文` `英语` `物理` `化学` `生物` `历史` `地理` `政治` |
| 3 | 时间限定词 | `上`/`下`+`册`、`第*周`、`第*单元`、`*月份`、`*月*日`、`国庆`、`寒假`、`暑假`、`期中`、`期末`、`月考`、`五一`、`十一`、`元旦`、`开学`、`假期`、`[春秋]季`、`[上下]学期`、`\d{4}年` |
| 4 | 日期形态 | `\d{4}[-./]\d{1,2}([-./]\d{1,2})?`（如 `2026-10-06`） |
| 5 | 空白符 | 半角与全角空格、制表符 |
| 6 | 分隔符 | `-` `_` `.` `/` `\` |
| 7 | Windows 非法字符 | `: * ? " < > \|` |

长度 ≤ 20 字符。

- **依据**：P3。年级是**学年属性**（今年七年级、明年八年级）—— 把年级写进目录名，等于埋一个
  "每年必须改名、改名就断引用"的定时炸弹。学科是**题**的属性，不是**人**的属性（`_建学生.mjs` 头注已讲透）。
- **正例**：`学生甲`、`学生乙`。小名即可，不必也不许是真名（隐私红线）。

### N3　保留名

小名不得取：`组卷`（见 C 系列保留名）、任何一个以 `_` 或 `.` 开头的名字、以及 Windows 设备名
（`CON`/`PRN`/`AUX`/`NUL`/`COM1`…`COM9`/`LPT1`…`LPT9`）。

### N4　学科目录名是闭集

`<库根>\<小名>\<学科>\` 的 `<学科>` ∈ `{数学, 语文, 英语, 物理, 化学, 生物, 历史, 地理, 政治}`，
且必须**恰好是该学生 `_索引.json` 的 `subjects` 键**（多一个 = 有卡无册；少一个 = 有册无卡）。

- **依据**：P4 + P2。学科名同时是 `subjects` 的键、是卡号前缀的来源、是 `_录题入库.mjs` 的落点判据。

### N5　卡目录名

`<前缀><4 位十进制序号>-<描述>`，例：`<小名>\数学\M0142-煮面条最少时间未作答\`。

| 项 | 规则 |
|---|---|
| 前缀 | 按学科唯一映射：数学`M` 语文`Y` 英语`E` 物理`P` 化学`C` 生物`B` 历史`H` 地理`G` 政治`Z` |
| 序号 | 4 位零填充，在**该学生该学科**内唯一、**只增不复用**（复用会撞历史台账） |
| 描述 | 非空、≤ **40** 字符、不含 Windows 非法字符、不含换行、不以空格或 `.` 结尾 |

- **40 这个数怎么来的（诚实写明）**：它是**防退化**的上限，不是审美。实测全库最长样本 36 字符
  （英语卡的描述天生偏长，如 `课文词块误写(oneself、the position、all the)`）。
  2026-11-06 立规范时初稿写 24，实测会逼着改 5 张**已入库**的卡名，并连带改
  `_原卷台账.json` / `_配图台账.json` / `_待确认.json` 等 4 份台账里的路径 ——
  代价是断引用风险，收益只是"短一点"。**判据存在的意义是防退化，不是逼人改历史**，故定为 40。
- **依据**：P2。卡目录名与台账的 `cardDir` 逐字对应，是"这道题在哪"的唯一定位串。

### N6　台账文件名

库级台账一律 `_` + 中文短语 + `.json` / `.md`，**住在库根**，不得下沉进学生目录。

- **依据**：P5。台账是跨学生的登记册（`_组卷台账.json` 记批次、`_原卷台账.json` 记整页、`_待确认.json` 记待裁量项），
  下沉到学生目录就变成"每个学生一本"，跨学生查询立刻失效。

### N7　保留目录名

程序保留目录一律 `_` 开头。**学生目录与学科目录不得以 `_` 或 `.` 开头**（生成器按此跳过，见 `生成状态.mjs` 的口径）。

### N8　通用文件名卫生

库根任何条目：不含 Windows 非法字符、不以空格或 `.` 结尾、不是 `.` / `..`。

### N9　唯一例外

`.git\` 与 `.gitignore` —— 库自身是 git 仓库（文本真源可回溯），这两个是版本控制的载体，不算数据条目。

### N10　原卷落点

整页原卷（`_原卷台账.json` 的 `page` 所指的那些扫描件）一律住在 `<库根>\<小名>\` **之下**，两种合法形态：

| 形态 | 何时用 |
|---|---|
| `<小名>\原卷\<批次>\` | 跨学科合卷，或批次尚未归到某一科 |
| `<小名>\<学科>\原卷\<批次>\` | 已知学科的整页 |

**禁止**把 `page` 指到库根顶层的无前缀目录。判据不是审美，是**能不能显示**：前端静态服务
（`_服务端.mjs`）只放行「路径段不以 `_` 开头」的位置，外加 `_原图\` / `_收件箱\` 两个例外；
`page` 指向别处 ⇒ 灯箱与「回原卷」直接 403。

- **机器判据已存在**：`_原卷台账.mjs 门禁` 的"库外 page"检查。本规范不另实现一份（P1：一份事实只住一个家）。

### N11　学科目录里允许有什么（闭集）

`<库根>\<小名>\<学科>\` 下**只允许**：

| # | 形态 | 是什么 |
|---|---|---|
| ① | `<前缀><4位>-<描述>\` | 卡目录（N5） |
| ② | `原卷\` | 整页原卷（N10）；其内可含 `_crops\`、`tiles\`（可重建的中间产物） |
| ③ | `待办证据\`、`_待确认证据-<YYYYMMDD>\` | 待办证据图暂存（"回原卷"链路要显示它） |
| ④ | `*.md` | 报告/记录件（给人看的产物，如批改报告） |
| ⑤ | `_` 或 `.` 开头的条目 | 程序件（扫描器一律跳过；`_备份-真源\` 属此类，见 N12） |

其余即违规。

**`<小名>\` 这一层允许什么**（与 N11 对称的闭集）：

| # | 形态 | 是什么 |
|---|---|---|
| ① | `_索引.json` | 该学生唯一一份索引（F1 真源） |
| ② | `<学科>\` | N4 闭集里的学科目录 |
| ③ | `原卷\` | N10 允许的**跨学科**原卷形态 |
| ④ | `_` 或 `.` 开头的条目 | 程序件（含 `_备份-真源\`，见 N12） |

**不放 `*.md` 报告件** —— 报告件只在学科目录层（N11④）。学生层是"身份 + 学科"的骨架，
塞进随笔文件会让"这个学生有哪几科"变得不可枚举（`findIndexes` 那类递归扫描也会多绕路）。

- **依据**：P4。判据不是洁癖：`生成状态.mjs` / `_录题入库.mjs` 等按"`_`/`.` 开头一律跳过"的口径递归找
  `_索引.json`，学科目录里塞进别的东西，"这是卡还是辅助目录"就只能靠猜。
- **不许拿"反正没人读"当理由往这儿放东西**：库是要能被人（和下一轮迁移）读懂的结构。

### N12　`_备份-真源\` 可以出现在任何层级

`_备份-真源\` 是 `_安全写.mjs` 的**滚动备份落点，写在被备份文件旁边**（`backupJson()`），
所以它既出现在库根，也出现在 `<小名>\` 与 `<小名>\<学科>\` 下。**任何层级都合法**，不是"下沉违规"。
同样地，N11 的 ⑤ 覆盖它。

- **依据**：P1 —— 备份落点由**唯一实现**决定；规范跟随实现（见 §一 的双向义务）。
  想让它集中到库根，得先改 `_安全写.mjs` 并复验 `_快照.mjs` / `tests\run.mjs` 的备份轮转放行判据；
  那是另一件事，不在"命名规范"的射程内。

### N13　共用区的条目命名（规则要盖满，别留没人管的地方）

`_收件箱\`、`_盲解\`、`_录题\`、`_撤卡留档\`、`组卷\`、`_笔形\` 是**跨学生共用**的区（同一个目录里放两个孩子的件），
所以它们的命名必须让"两个孩子的东西一眼分得清、且写法完全一致"（P9）。

| 位置 | 条目命名 | 谁写 |
|---|---|---|
| `_收件箱\` | 批次目录 `<YYYY-MM-DD>-<小名>-<学科>[-<描述>]` | 人工丢照片 |
| `_盲解\` | `<小名>-<学科>-盲解清稿[-第2路｜-重盲解].md` | `_盲解复核.mjs` |
| `_录题\` | `t-YYYYMMDD-HHmmss-<6位hex>.json` | `_录题任务.mjs` |
| `_撤卡留档\` | 批次式 `<YYYY-MM-DD>[-<描述>]\`；单卡式 `<卡号>-<描述>-<YYYY-MM-DD>-<原因>\` | 撤卡流程 |
| `组卷\` | `<YYYY-MM-DD>-<小名>-<重做卷｜答案册>-<HHmm>.pdf` | 组卷链路 |
| `_笔形\` | `<小名>\<标签>\<YYYY-MM-DD>-<4位序号>.<ext>`。**标签自由命名**（它只是样本分组），但每份样本必须能被 `_笔形台账.json` 点名 | 笔形入库 |

两条硬规矩：

1. **日期一律 `YYYY-MM-DD`**，不许 `YYYYMMDD` 混用。同一种东西两种日期写法，就是"没人管"的典型症状。
   （例外：`_录题\` 的任务号 `t-YYYYMMDD-…` 是**时间戳型 ID**，不是日期标注，且已 100/100 统一 —— 保持。）
2. **`<描述>` 可省**：`2026-11-05-甲-数学` 合法 —— 描述是"同日同人同科有多批时"的区分项，不是身份。
   但**少了 `小名` 与 `学科` 之间的分隔符就算违规**（`2026-11-01-甲物理-…` ✘，小名成了"甲物理"）。

- **依据**：P9。这一节是**补出来**的：这三处原先规范没写，实际结果就是"两种写法并存、谁都没错"。

## 三、库根顶层闭集（C 系列）

### 3.0　哪些是"一人一套"、哪些是"全库共用一套"（P9 的结构化落地）

用户裁定「一个孩子一套数据，两个孩子两套数据，但规则完全复用」。这句要落成结构，必须把
**"一套数据"到底指什么**说清 —— 库里有两种东西，混起来会让"再加一个孩子"变成改结构：

| 归属 | 条目 | 为什么 |
|---|---|---|
| **一人一套**（per-child） | `<小名>\`（含 `_索引.json`、学科目录、卡目录、`原卷\`） | 身份、进度、复习流水、错因，天然按人分 |
| **全库共用一套**（cross-child） | `_原图\`、`_影像备份\`、`_备份-真源\`、`_收件箱\`、`_录题\`、`_盲解\`、`_撤卡留档\`、`_笔形\`、`_工具\`、`组卷\`、以及**全部库根台账** | 影像是**内容寻址的字节**（同一张照片被两个孩子引用时只该存一份）；台账是**跨学生的登记册**（`_组卷台账` 记批次、`_原卷台账` 记整页、`_待确认` 记待裁量项） |

**推论（这条是硬规矩）**：共用区里**凡是"能归属于某个孩子"的条目，名字里必须带 `<小名>`** ——
否则"这是谁的"只能靠猜。这就是 N13 为什么要求 `_收件箱\`、`_盲解\`、`组卷\` 的条目名里带小名，
而 `_原图\`（内容寻址）不需要：它的对象按内容共享，来源由 `_原图台账.sources[]` 记录。

**再加一个孩子应当零结构改动**：只需新建 `<新小名>\`（走 `_建学生.mjs`），共用区、台账、门禁**一行都不用改**。
G11 是按"遍历所有学生"写的，不是"写死两个孩子"。

**规则本体**：库根顶层的每一个条目，**必须**在下表之内。表外的任何东西 = 违规（P4）。
新增一类 = 改本文 + 改门禁 + 加阴性对照，三件一起做，缺一不算。

### 3.4　明令禁止的东西（三个作用域，别混）

**① 库根顶层**：不得出现任何未列入 3.1 / 3.2 / 3.3 的条目（P4 闭集）。

**② 库内任何位置**（不限顶层）：不得出现
`*.bak-*`、`*.bak`、`*.old`、`*.orig`、`*.tmp-*`、`_probe\`、`_tmp*\`、`_快照\`。
备份件只有两个合法去处：`_备份-真源\`（库内）或库外。

**③ 只在特定位置合法的**：`tiles\`、`_crops\` 只能出现在卡目录/原卷目录**内部**
（它们是可重建的中间产物，判据见本行与 `_原图.mjs` 的扫描排除项；`_影像备份.mjs` 已按 P10 退休，它原来的 `REBUILDABLE_RE` 不再是真源）；出现在库根顶层即违规。

**豁免（穷举，各有理由）**：

| 位置 | 为什么豁免 |
|---|---|
| `_备份-真源\` 内部（**任何层级**） | 它本身就是"文本真源的滚动快照"区，文件名带 `.bak-` 是历史留存；落点由 `_安全写.mjs` 的 `backupJson()` 决定（N12） |
| `_影像备份\` 内部 | 同上；且 `_影像备份.mjs` 在内容变化时会就地留 `<同名>.bak`（覆盖前保底） |
| `_原图\_快照\` | 内容寻址库的**内部快照清单**（只记录"某时刻有哪些 sha"），`_原图.mjs` 与 `_影像备份.mjs` 都显式把它排除在扫描与备份分母之外。**这是 `_快照\` 唯一的合法位置** |

- **依据**：P5 + P6。过程件的唯一合法落点是 `%LOCALAPPDATA%\拾光小册\proc\`（`_过程目录.mjs`），删掉它永远安全。

**已知边界（诚实写明）**：
- 本门禁管"名字形态与目录关系"，**不管"内容是否该留"**。一个合规命名的文件也可能毫无价值 ——
  那属于内容审计（`_体检.mjs` / `_原图.mjs 校验`），不是本文的判据。
- ② 的名字表是**穷举**的。要新增一种残渣形态 = 改本文 + 改门禁 + 加阴性对照。
- Win32 上造不出含 `?`/`*` 的目录（当场 EINVAL）⇒ G5 的"非法字符"子判据在本机**没有阴性对照**（判据保留）。

## 四、索引形态（F 系列）

### F1　一个学生 = 恰好一份 `_索引.json`

位置 `<库根>\<小名>\_索引.json`，形态：

```json
{ "student": "<小名>", "grade": "七年级", "subjects": { "数学": { "items": [] } }, "note": "", "updatedAt": "" }
```

**禁止**按学科拆成多份（`<小名>\数学\_索引.json` + `<小名>\英语\_索引.json` + …）。

- **依据**：P1。拆成多份就是"两份并列真源"：同一学生的复习状态散在多处，跨学科统计要先合并，
  而 `_录题入库.mjs` 的 `findTarget()` 在发现同一学生多份索引时会**直接拒收**并打印"请先合并成一个"。
  正典由 `_建学生.mjs` 定义（它建的永远是学生级一份索引）。

### F2　卡目录位置

`<库根>\<小名>\<学科>\<卡目录>\`，卡目录四件套：`题干.html` / `错题记录.md` / `原卷截图.jpg` / `_裁图记录.json`。
学科目录里除卡目录之外允许什么，见 **N11**。

### F3　写入归属

索引只由工具写；其中 `answerSlots` / `answerMode` **只能**由 `_作答门禁.mjs` 写入（既有红线，手工改不算数）。

**F3·补（2026-11-13 批次 4）·教辅版本字段 `srcBook` / `srcEdition`**

- 归属：由 `_录题入库.mjs` 写（与 `source` / `sourceDate` 同路），**不是**门禁字段。
- **可选**：不进 `required`。老卡没有这两个字段照样合法（否则整库一夜变红）。
- 为什么要有：同名教辅的**地区专版 / 印次**不同时，同一道题的答案可能不同 ——
  这是"答案对不上"时的**第一顺位排查字段**（先确认双方说的是不是同一本书、同一版）。
  看不清就留空，**不许猜**（猜错版本比留空更坏）。
- 长度上限 120 字符；入库器对两处路径（新卡 / 改卡）都写，且**进幂等摘要**
  （只改版本重提必须被当成新内容，不许被幂等跳过）。

**F3·补2（2026-11-13 批次 4）· 难度在线估计 `it.elo` / 学科索引的 `ability`**

- 归属：由 `_标记复习.mjs` 在**判分落库时**更新（与 `reviews` / `errorCount` / `nextDue` 同一处）。
  算法是零副作用纯函数模块 `src\tools\_难度.mjs`。
- **只加字段、不动既有判据**：`errorCount` / `nextDue` / `passStreak` / `reviewStatus` 一个都不许被搅动
  （它们是复习流的下游输入）。用例里有一条断言专门钉住"更新点在 errorCount 之后、既有判据一行未动"。
- 口径：`it.elo`＝这道题的难度估计（"能力到多少的孩子有 50% 把握做对"）；
  `ability` 落在**学科索引**上 ⇒ 语义是"**该生该科**的能力"（数学能力 ≠ 英语能力，本来就不该混）。
- **答对 ⇒ 能力升、题目难度估计降**（题目是"对手"，孩子赢 ⇒ 对手显得弱）。这两个方向相反不是笔误。
- 与人工 `difficulty` 的关系：**不替代、不修改**它 —— 人工三档只用来给新卡一个**先验**
  （1420 / 1500 / 1600），之后两套并存、各说各的话。

**F3·补3（2026-11-13 批次 4）· 错因的「阶段维」`causeStage`**

- 归属：由 `_录题入库.mjs` 写（与 `causeCode` / `causeLayer` 同路）；**AI 在录题时填**，口径见
  `src\recipes\_core\cause.md` 的「阶段维」章节。
- **可选**：不进 `required`。老卡没有它照样合法；空串表示"拿不准"（**允许，且比猜一个强**）。
- 取值**只有四个**：`审题` / `转化` / `求解` / `书写`（另有空串）。
  **枚举外的值一律拒收**（入库前置检查会进 `problems`）——这一维的全部意义就是"可筛可统计"，
  放一个自由文本值进来等于没加，还会**静默污染趋势**。
- 它与 K/L/S **正交**：K/L/S 说"**什么性质的错**"，阶段说"**错在解题的哪一步**"。
  两者互不替代：`K2 法则误用` 可能发生在求解阶段，也可能发生在转化阶段。
- 为什么要有：只用 K/L/S 时分布极偏（真库 `K1` 一码占 **39%**，79/202），
  而"错在哪一步"此前只能写进 `causeNote` **自由文本**、机器读不了 ⇒ 筛不动、出不了趋势。
- 前端：题库筛选台有「阶段」一行芯片（含「未填」——那是**待补录清单**，不是"全部"）。

**F3·补4（2026-11-13 批次 4）· 复习流水里的「谁判的」`reviews[].by`**

- 归属：由 `_标记复习.mjs` 的**批改**动作写（`--by`），壳只做透明转发。
- 取值**只有三个**：`家长` / `孩子` / `AI辅助`（另有空串＝未记）。**枚举外的值一律拒收**
  （自由文本进来这一维就统计不了，与错因阶段维同一个道理）。
- 前端**不让人手选**：由孩子模式**派生**（孩子模式 ⇒ `孩子`，否则 `家长`）——
  这个派生本来就准（"孩子模式"的定义就是让孩子自己判），多一个选择器只会多一处忘填/填错。
- 为什么要有：孩子模式下自评时，界面若暗示"判对就能少做"，就会诱导**挑好判的判对**。
  记下"谁判的"之后，家长一眼能看出哪些记录是自评、自评的正确率是否异常偏高——
  这是**数据自证**，比"我觉得你在放水"好谈得多。
- 拒收发生在**写盘之前**（`writeJson` 之前），所以非法参数不会写坏已有记录。

### F4　派生物

`_状态.json`、`_复习队列.md`、`_待确认清单.md`、`首页.html` 是派生物：可随时重算、**不是真源**。

`_原卷待定位-按批次.md` 同样是派生物（**2026-11-13 起可重算**：`node src\tools\_原卷台账.mjs 工单`）。

| G11 | **P9** + N13 | **跨学生同构**：① 每个学生的**必答项**必须同构（目录名 = `student` 字段、恰好一份学生级索引、学科目录 = `subjects` 键、每层条目 ∈ 闭集、"一个学生一份索引"）；② 跨学生的**共用命名规则**必须对**每一个**学生都成立（`_收件箱\` 批次名、`_盲解\` 清稿名、`_录题\` 任务号、`_撤卡留档\` 条目名、`组卷\` 成品名、`_笔形\` 文件名的日期形态）|

**G11 的"同构"怎么判（写清边界，免得又变成恒真或恒假）**：

- **必答项**（少一个就红）：目录名等于 `student`；`<小名>\_索引.json` 恰好一份、形态为 `subjects{}`；
  学科目录集合 === `subjects` 键集合；学生层与学科层的每个条目都在 N11 的闭集内。
- **可选顶**（有则须合规，没有不红）：`原卷\`、`待办证据\`、`*.md` 报告件、任意 `_`/`.` 开头程序件
  （含 `_备份-真源\`）。**"甲有原卷、乙那科没有"是内容差异，不是规则差异，不许判红。**
- **跨学生命名**：对每个学生分别算出"它在共用区里的条目合规率"，**必须都是 100%**；
  而不是"整体合规率 100%"（那会被人数多的那个学生掩盖掉另一个人的问题）。

门禁必须**能红**：只测正例的检查是恒真的，等于没测 —— 所以 `tests\neg-data-area-rules.mjs`
在合成库上逐条制造违规并断言每条都被判红（阴性对照），另加一组合法库断言全绿（防假阳）；
还要有一条**自证**：临时把某条判据改成永假，阴性对照必须失败（证明判据本身是活的）。

**作用域（诚实写明边界）**：本门禁管的是**用户的真库**（配置的库根）与**迁移验收**。
`fixtures\` 下由 `make-fixture-lib.mjs` 造的合成库**不受本门禁约束** —— 那些库是**故意**造成畸形形态的
（例如"同一学生拆两份学科索引"），用来证明工具链**容错读旧形态**。门禁不得接进 `tests\run.mjs` 去判它们，
否则等于要求工具链放弃对旧库的兼容。

### 七.1　路径改写的判据（搬迁/改名时唯一允许的做法）

> 机器判据（唯一实现）：`node src\tools\_路径改写.mjs 预演|执行|对账 --map '<旧>=<新>'`；
> 阴性对照 `node tests\neg-path-rewrite.cjs`（证明三条判据真会红、`grade` 不会被误改、死链对拍不是恒红）。

改写范围**不止 JSON**。库里的路径有三种载体，**三条判据各管一种**，缺一条就会漏改：

| # | 载体 | 判据 |
|---|---|---|
| ① | **相对路径**（JSON 的值与**对象键**、`.md` 里成段的路径） | 值以 `<旧相对路径>` 开头 → 换前缀（**必须带分隔符**） |
| ② | **绝对路径**（`_录题\*.json` 的 `image.rel`、卡目录 `_裁图记录.json` 的 `src`、`错题记录.md` 的「原图：」行） | 值以**盘符根**开头且含 `/<旧相对路径>` 段 → **只换那一段** |
| ③ | **非路径标识**（如 `_原图台账.json` 的 `objects[*].batch` 批次标签） | 值**恰好等于**旧名 → 整串替换 |

- **为什么 ①必须带分隔符**：初版判据里多了一条"整串相等"，于是 `_索引.json` 的 **`grade` 字段**
  （值恰好是 `九年级`）被当成路径改成了小名 —— 一个非路径字段被静默改坏。
  普查实测：没有任何需要改写的路径值是"光秃秃一个段名"。
- **为什么 ②必须存在**：库里有**绝对路径**（`_录题\*.json` 记的是入库时那张照片的绝对路径）。
  只按"相对前缀"判，这类值一个都改不到 —— 实测第一轮就漏了它们，由独立复核方对"改后是否仍指向存在文件"时抓出。
- **为什么 ③必须单列**：`batch` 是**标识**不是路径（没有分隔符），只能整串比。
- **`*.md` 是路径的第三种载体（2026-11-06 补，血的教训）**：卡的 `错题记录.md` 有「原图整页：」/「原图：」这样的
  **指针行**，`_撤卡留档\…\_本批说明.md` 有恢复指引里的路径。第一版改写**只实现了 JSON**，
  于是 102 份 `.md` 的指针行在改名后变成死链（其中 100 份是第一轮漏的，独立复核方只看到第二轮那 4 份）。
  **`.md` 里改不改的判据（精确到不误伤历史叙述）**：一个路径 token 被改写，当且仅当
  **① 它现在解析不到（死链）；② 把旧段名换成新段名后能解析**（⇒ 是**改名**把它变死的，不是本来就坏）。
  这条天然放过"本来就失效"的库外路径（`D:\化学\…`、`_work-*\`）与历史叙述里"当时有效、如今已删"的路径。
- **不改**叙述与溯源字段（`source` / `note` / `detail` / `evidenceFix` / `origFix` / `answer` /
  `dispositionNote` …）—— 那是历史留痕（AGENTS.md 红线 6「不改写历史」）。这些字段的值从**不以**旧段名开头，
  ① 类锚定判据自动跳过它们。
  **派生物同理**：`_待确认清单.md` / `_复习队列.md` 里由叙述字段渲染出来的旧路径**不手改** —— 改了也会被重算覆盖。
- **例外（必须改）**：`_原图台账.json` 的 `objects[*].sources[]`。它不是叙述，是 `_原图寻址.mjs`
  的 `pathShas()` **反查表的键来源**；不改它，那些"盘上已不在、只能靠影像备份按同路径兜底"的
  `page` 就永远解析不到。**这条例外要单独声明**，不要假装它属于"路径字段"的默认集合。
  它的正确性判据很硬：**每条新值必须 === 新前缀 + 旧值去掉旧前缀后的原样余部**（逐字符）。
  2026-11-06 实测：846/846 全部是纯前缀替换、`sources` 条数漂移 0 ⇒ provenance 的"指向"没被改坏。
- **不改** `_备份-真源\` 下的任何快照 —— 备份是冻结证据，改了它就不是备份了。
- **改完必须独立复核，两套口径都要**：
  - **逐字段对拍**：把"搬迁前备份"与"现在"对拍，每处变化分类成「合法（旧值/旧键以旧段开头）」或「可疑」；**可疑必须为 0**；
  - **死链对拍**（比"有没有旧名"更强）：全库扫路径 token，凡"**现在解析不到、改名后能解析**"的即为本次制造的死链，**必须为 0**。
    这一条能抓住"名字改了但某个载体没跟着改"，而前一条抓不住 —— 它才是 2026-11-06 那 102 份 `.md` 的判据。
