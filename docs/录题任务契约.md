# 录题任务契约（任务记录 / 返回信封 / 三层校验）

> 立：2026-11-02（批次 1「任务绑定」）｜引擎：`src\tools\_录题任务.mjs`（唯一读写入口）
> 对应建议书 §4「任务绑定及兼容」。**这份文件是"一次录题到底对应哪张图、哪版配方、哪次任务"的唯一口径。**

## 一、要解决的问题

页面把任务单交给 AI 之后，程序什么都不留：AI 回传的 JSON 只做格式校验。
于是**把 A 的结果贴进 B** 在程序看来完全合法——卡会挂到错的题上，而且事后无从回溯。
这一类错误必须由程序拦，不能靠人记得。

## 二、任务记录（`<库根>\_录题\<taskId>.json`）

**它是用户数据**（随库走、走 `_安全写.mjs` 原子写），不是过程件：
删掉它就等于删掉"这批卡当时是哪张图、哪版配方产的"。

| 字段 | 说明 |
|---|---|
| `schema` | 固定 `glimmernote.ingest-task/v1` |
| `taskId` | `t-YYYYMMDD-HHmmss-<6位随机>`。**同图同配方再生成仍是两个任务**——否则"错配必须被发现"这条没法验 |
| `createdAt` | 本地时间（带时区偏移） |
| `recipe` | `{id, version, fingerprint}`；`fingerprint` = `_配方.mjs 指纹`（layers + prompt + 反例） |
| `image` | `{sha256, rel}`：原图**完整 sha256** 与库内相对路径 |
| `subject` / `cards` | 学科；所采用的用户经验卡 `[{packId, cardId, version}]`（批次 2 起才非空） |
| `contractDigest` | sha256(实际拼入正文 + `\0` + `schema.json`) —— **现有"指纹"不含 schema**，故另立一个摘要，专供"这批卡是按哪版契约收的" |
| `taskDigest` | sha256(任务单全文) —— 用来证明"当时给的到底是哪份任务单" |
| `taskText` | 任务单全文（归档；包升级/删除后仍能解释旧任务） |
| `confirmedAt` / `confirmNote` | 第三层：**只由人**跑 `确认` 才写 |

## 三、返回信封（可选，但推荐）

AI 回传允许两种形态：

```jsonc
// ① 有信封（推荐；携带"这是哪个任务"的身份）
{ "envelope": { "schema": "glimmernote.ingest-result/v1",
                "taskId": "t-20261102-214122-fe4219",
                "imageSha256": "<64 hex>" },
  "result": { /* 原业务对象：pageSummary / cards / skipped */ } }

// ② 裸对象（旧格式，仍然收）
{ /* pageSummary / cards / skipped */ }
```

**为什么用外层信封**：`cards` 的 schema 设了 `additionalProperties:false`，往里塞 `taskId` 会被拒收；
信封把任务身份放在业务对象之外，**不动**既有契约（建议书 §4 的原话就是这条）。

## 四、三层校验（`绑定校验 <taskId> --in <file>`）

| 层 | 判据 | 不通过时 |
|---|---|---|
| ① 格式 | 交给 `_配方.mjs 校验`（**唯一实现**，界面与 CLI 共用同一份；它自己也会剥信封） | exit **1** |
| ② 与任务及原图匹配 | 信封 `taskId` == 记录 `taskId`；信封 `imageSha256` == 记录图 sha；每张卡 `sourceImageSha256` == 记录图 sha | exit **3**（给具体原因：哪个字段、哪个值、和谁不符） |
| ③ 内容已人工确认 | 记录里的 `confirmedAt`（人跑 `确认` 才写） | **不改退出码**，但输出必须写明"**第三层未完成**"——不许假装全通 |

**裸对象（无信封）**：照旧走格式校验，输出明确写"**未与任务关联**"——**兼容不等于把旧结果算成已验证**。

## 五、退出码

| 码 | 含义 | 属于 |
|---|---|---|
| 0 | 通过 / 成功 | 新旧命令 |
| 1 | 格式不通过 | 新旧命令（语义不变） |
| 2 | 任务不存在 / 用法错 | 新旧命令 |
| 3 | **与任务不匹配**（跨任务、图不一致） | **只有 `_录题任务.mjs`**（旧命令的码表不动） |

## 六、命令

```powershell
# 生成任务单并留痕（页面点「生成任务单」时走的同一条路）
node src\tools\_配方.mjs 组装 --recipe ingest-page --subject 数学 --image _收件箱/x.jpg --task --out task.md
node src\tools\_录题任务.mjs 列 [--json]
node src\tools\_录题任务.mjs 看 <taskId> [--json]
node src\tools\_录题任务.mjs 绑定校验 <taskId> --in cards.json     # 三层
node src\tools\_录题任务.mjs 确认 <taskId> --note "人工看过"
```

## 七、边界（写清，别假装没有）

1. **程序不改 AI 的行为**：任务号只写在任务单第五节 + 要求信封回传；AI 不带信封也能收，只是**无法验证任务归属**（输出里会明说）。
2. **契约真源是本文**。`schema.json` 改版后，旧任务的 `contractDigest` 会与新版不同——这是**特性**（能看出"这批卡是按哪版契约收的"），不是缺陷；需要重放时按 `taskText`（记录里留了全文）重跑。
3. **`数据\_录题\` 是新写入路径**：它**不进** `tests\run.mjs` 的派生白名单（白名单只开 `_状态.json` 与 `_备份-真源\` 两扇门，见 `docs\过程文件规范.md`）。因此**测试一律用副本库**；谁要用真库跑，先想清楚"这轮会不会生成任务"。
4. **界面部分尚未接线**：批次 1 已提供 CLI 与信封；页面把 `--task` / 选卡参数送进引擎需要改壳的参数透传（C# 逐项映射，壳当前只映射 6 类固定参数），列为批次 1 的下一项。
