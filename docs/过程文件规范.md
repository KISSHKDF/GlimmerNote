# 过程文件规范（缓存 / 预览 / 派发单 / 临时件住在哪、谁清）

> 立：2026-11-02（用户质问："过程中的文件不止 `_probe` 吧？应该有无数处吧？既然是过程性文件，做完就该处理掉。"）
> 实测依据：`docs\..\work\glimmer-dsh-plan-20261102\recon\R7-过程文件清单.md`（全量清点：35 个落点类别；
> 清理前磁盘上压着 **约 10.2 GB** 该清未清的残留，2026-11-02 已清 10.13 GB）。
> 本文只写**判据与落点**；具体某个文件属于哪一类，以清点表为准。

## 一、四类，四个家（这是全文的核心）

| 类 | 定义（判据） | 唯一落点 | 能不能删 |
|---|---|---|---|
| **① 真源** | 丢了不可复现；重建只能靠原始输入 | 库根 `数据\`（学生/批次卡目录、`_收件箱\`、`_原图\`、9 个真源 JSON/MD、`_撤卡留档\`） | **绝不能删** |
| **② 显式备份** | 真源的安全副本，由 `_安全写.mjs` / `_影像备份.mjs` 写真源时顺带产生 | 库根 `数据\_备份-真源\`、`数据\_影像备份\` | 只在明确要清历史时删 |
| **③ 过程件** | 跑一次就产生、删掉不影响任何结果（缓存/预览/派发单） | **`%LOCALAPPDATA%\拾光小册\proc\`**（唯一实现 `src\tools\_过程目录.mjs` 的 `procPath()`；`GLIMMERNOTE_PROC` 可覆盖） | **整目录删永远安全** |
| **④ 临时件** | 一次调用内用完即弃（子进程 IO、夹具库、浏览器 profile） | `%TEMP%\`（前缀 `gn-` / `ctb-`）；**必须 finally + 启动双清** | 随时可删 |

**库根（`数据\`）只许放 ① 与 ②。** ③④ 出现在库根一律是缺陷。

## 二、为什么过去会漏（机制，不是"不小心"）

`tests\run.mjs` 的"真库零写入断言"只放行两项派生件：

- `run.mjs:117` `DERIVED_CACHE = new Set(['_状态.json'])`
- `run.mjs:183/186` `_备份-真源\`（且**只在副本库**放行轮转）

其余一切写在库根里的过程件（`_probe\`、`_复习队列.md`、`_盲解\`、`_笔形\`…）都**不在白名单**，
于是它们一旦被工具重写，收尾断言就判红 —— `run.mjs:104-109` 注释自陈的"干净 HEAD 上 quick 恒红"
就是这么来的（2026-11-02 实测：`_原卷台账.mjs` 的 `sizesOf()` 在失败分支穿透写 `_probe\_图尺寸.json`）。

**结论：不要靠"再往白名单加一项"来消红。** 白名单只开两扇小门是对的；
要修的是"过程件为什么会长在库根里"——现在唯一出口是 `procPath()`。

## 三、新代码怎么写（照抄这三句）

```js
import { procPath } from './_过程目录.mjs';
const CACHE = procPath('_图尺寸.json');        // ③ 过程件：缓存/预览/派发单
// ④ 临时件：用 os.tmpdir() + mkdtempSync，并在 finally 里 rmSync（见下面"已知欠账"第 1 条）
```

三条硬纪律：

1. **不许再写** `path.join(ROOT, '_probe', …)`（`ROOT` 是用户库根）。
   唯一范本：`_原图.mjs:157` 的**启动时清扫**——它是全仓唯一做了启动清扫的工具，新工具照它抄。
2. **只读命令不许落盘**：`覆盖/门禁/--dry` 这类"看"的命令，缓存也不许写（`--dry` 连过程目录也不写）。
3. **写入前先判断"内容真的变了"**：原子写（临时文件 + rename）会让 `mtime` 必然前进，
   "没改也写"在零写入判据眼里就是一次写事件。用 `writeIfChanged()` 那种先比内容再决定写不写。

## 四、清理入口（机械可执行）

```powershell
# ① 库根不该出现的写入（应只有 ① / ② / 派生物白名单里的 _状态.json）
$env:CTB_DATA = "<运行区>\数据"
node tests\run.mjs quick        # 收尾的"真库零写入断言"就是这条判据

# ② 过程目录随时可整删
Remove-Item "$env:LOCALAPPDATA\拾光小册\proc" -Recurse -Force

# ③ 临时件残留巡检（这两条曾一次报出 8.3 GB）
(Get-ChildItem $env:TEMP -Directory | Where-Object { $_.Name -like 'ctb-*' -or $_.Name -like 'gn-*' } | Measure-Object).Count
(Get-ChildItem $env:TEMP -File      | Where-Object { $_.Name -like 'ctb-*' -or $_.Name -like 'gn-*' } | Measure-Object).Count
```
