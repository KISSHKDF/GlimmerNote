## 一、四类，四个家（这是全文的核心）

| 类 | 定义（判据） | 唯一落点 | 能不能删 |
|---|---|---|---|
| **① 真源** | 丢了不可复现；重建只能靠原始输入 | 库根 `数据\`（学生/批次卡目录、`_收件箱\`、`_原图\`、9 个真源 JSON/MD、`_撤卡留档\`、**`_录题\`**、**`_修订\`**） | **绝不能删** |
| **② 显式备份** | 真源的安全副本，由 `_安全写.mjs` / `_影像备份.mjs` 写真源时顺带产生 | 库根 `数据\_备份-真源\`、`数据\_影像备份\` | 只在明确要清历史时删 |
| **③ 过程件** | 跑一次就产生、删掉不影响任何结果（缓存/预览/派发单） | **`%LOCALAPPDATA%\拾光小册\proc\`**（唯一实现 `src\tools\_过程目录.mjs` 的 `procPath()`；`GLIMMERNOTE_PROC` 可覆盖） | **整目录删永远安全** |
| **④ 临时件** | 一次调用内用完即弃（子进程 IO、夹具库、浏览器 profile） | `%TEMP%\`（前缀 `gn-` / `ctb-`）；**必须 finally + 启动双清** | 随时可删 |

> **`_录题\` 属①真源（2026-11-03 补登）**：`数据\_录题\<taskId>.json` 是录题任务记录
> （由 `src\tools\_录题任务.mjs` 走 `_安全写.mjs` 写，批次 1 新增的写入路径）。
> 删掉它就等于删掉"这批卡当时是哪张图、哪版配方产的" ⇒ **绝不能删**，且**不进派生白名单**
> （它一被写就该判红；判据与对照见 `tests\run.mjs` 的 `LIB_USER_DATA_DIRS` 与同处的阴性自证 ⑦⑧）。
> 口径另见 `docs\录题任务契约.md §七.3`。

## 二、为什么过去会漏（机制，不是"不小心"）

`tests\run.mjs` 的"真库零写入断言"只放行两项派生件：

- `run.mjs:117` `DERIVED_CACHE = new Set(['_状态.json'])`
- `run.mjs:183/186` `_备份-真源\`（且**只在副本库**放行轮转）

其余一切写在库根里的过程件（`_probe\`、`_复习队列.md`、`_盲解\`、`_笔形\`…）都**不在白名单**，
于是它们一旦被工具重写，收尾断言就判红 —— `run.mjs:104-109` 注释自陈的"干净 HEAD 上 quick 恒红"
就是这么来的（2026-11-02 实测：`_原卷台账.mjs` 的 `sizesOf()` 在失败分支穿透写 `_probe\_图尺寸.json`）。

**结论：不要靠"再往白名单加一项"来消红。** 白名单只开两扇小门是对的；
要修的是"过程件为什么会长在库根里"——现在唯一出口是 `procPath()`。

## 三、新代码怎么写（照抄这三句）

```js
import { procPath } from './_过程目录.mjs';
const CACHE = procPath('_图尺寸.json');        // ③ 过程件：缓存/预览/派发单
// ④ 临时件：用 os.tmpdir() + mkdtempSync，并在 finally 里 rmSync（见下面"已知欠账"第 1 条）
```

三条硬纪律：

1. **不许再写** `path.join(ROOT, '_probe', …)`（`ROOT` 是用户库根）。
   唯一范本：`_原图.mjs:157` 的**启动时清扫**——它是全仓唯一做了启动清扫的工具，新工具照它抄。
2. **只读命令不许落盘**：`覆盖/门禁/--dry` 这类"看"的命令，缓存也不许写（`--dry` 连过程目录也不写）。
3. **写入前先判断"内容真的变了"**：原子写（临时文件 + rename）会让 `mtime` 必然前进，
   "没改也写"在零写入判据眼里就是一次写事件。用 `writeIfChanged()` 那种先比内容再决定写不写。

## 四、清理入口（机械可执行）

```powershell
# ① 库根不该出现的写入（应只有 ① / ② / 派生物白名单里的 _状态.json）
$env:CTB_DATA = "<运行区>\数据"
node tests\run.mjs quick        # 收尾的"真库零写入断言"就是这条判据

# ② 过程目录随时可整删
Remove-Item "$env:LOCALAPPDATA\拾光小册\proc" -Recurse -Force

# ③ 临时件残留巡检（这两条曾一次报出 8.3 GB）
(Get-ChildItem $env:TEMP -Directory | Where-Object { $_.Name -like 'ctb-*' -or $_.Name -like 'gn-*' } | Measure-Object).Count
(Get-ChildItem $env:TEMP -File      | Where-Object { $_.Name -like 'ctb-*' -or $_.Name -like 'gn-*' } | Measure-Object).Count
```

## 六、`_待确认.json` 的条目字段（真源字段枚举）

`<库根>\_待确认.json` 是「需要人回答的悬空问题 + 人工判读留痕」的**唯一真源**（`_待确认清单.md` 只是渲染页，
由 `_待确认.mjs 清单` 生成，勿手改）。条目上有哪些字段、谁能写，以本节为准：

| 字段 | 形状 | 谁能写 | 说明 |
|---|---|---|---|
| `id` `student` `subject` `cardId` `source` `qRef` `box` `kind` `askWho` `question` `detail` `raisedAt` `status` `answer` `resolvedAt` `evidence` | 见 `_待确认.mjs` 的 `加` | `_待确认.mjs` 的写入子命令 | 建账与处置的既有字段（批次 4 **一字未改**） |
| `evidenceFix` `evidenceNote` `boxFix` `origFix` `cardIdFix` | 字符串 | `定位` | 「改了指到哪里」的留痕（不静默替换） |
| `questionFix` `questionBefore` `detailFix` `detailBefore` `qRefFix` `qRefBefore` | 字符串 | `改问题` / `改详情` / `去黑话` | 改写给人看的文本时的留痕 + 原文 |
| `verdict` `verdictNote` `verdictAt` `disposition` `dispositionAt` `dispositionNote` | 字符串 | `判定` / `处置` | 五段闭环的后两段 |
| `corrections[]` | `[{at, why, scope, target}]`，**append-only** | `纠因` | 家长/用户「为什么纠正」的原话（批次 3） |
| `candidates[]` | `[{candId, at, kind, target, payload, payloadDigest, status, adoptedAt}]`，**append-only** | `候选` 追加；`status`/`adoptedAt` 由 `采用` 与 `作废候选` 改 | 修订**草案**（还没进库的想法）。`candId = c-<sha256(kind\|target\|payloadDigest) 前 12 位>`；`status ∈ 待采用 / 已采用 / 已作废`；`payloadDigest = sha256(正文按 LF 归一)` |
| `revisions[]` | `[{at, by, candId, kind, target, written[], note}]`，**append-only** | **只有 `采用`** | 正式写入的留痕：谁在什么时候把哪段正文写进了哪些**库内相对路径** |

**两条硬纪律**（在 `_待确认.mjs` 里是可执行的判据，不是注释）：

1. **只增不改**：新字段一律追加到条目上，既有字段一个字不动 —— `采用` 只 `push` 进 `revisions[]`
   并改候选记录的 `status`/`adoptedAt`，不碰 `question`/`detail`/`status`/`answer`。
2. **形状读不懂响亮拒绝**：`candidates`/`revisions` 存在但不是数组 ⇒ **exit 2 且台账一字不动**
   （BUG-02 那一族：读不懂就"当成空表"、随后覆盖，会永久丢掉人工修订链，不可再生）。

> 字段的**行为契约**（子命令、退出码、三类错误的判据）不在这里，在 `docs\录题任务契约.md`「候选与修订链」——
> 一份事实一个家：本节只说"有哪些字段、谁能写"。

## 七、`_修订\`（新真源目录，批次 4）

`<库根>\_修订\<kind>\<目标>\<candId>.md` —— 「候选修订正式写入」的落点（唯一写入者：`_待确认.mjs 采用`）。

- 属 **① 真源**：内容是人工判断的产物，删掉不可复现（`_待确认.json` 的 `revisions[].written` 会指向不存在的路径）；
- **只增不改**、按 `candId` 命名（文件名就是候选号）；正文是**候选的纯函数**（不含采纳时刻），
  因此"同一候选重复采用"能逐字节比对内容、半截失败后重跑能判定为幂等跳过，而不会因为时间戳不同被误判成"人工改过"；
- 落点已存在且内容不同 ⇒ `采用` **拒绝覆盖**（exit 1）——「人工改过这条修订」与「候选号串号」两种可能都必须由人看，
  工具不替人挑一个；
- 写入走 `_安全写.mjs` 的**锁 + 事务**（与 `_待确认.json` 一次提交、失败整体回滚），不做就地覆盖；
- 采纳时点与写入清单**不住在这里**，住 `_待确认.json` 的 `revisions[]`（一份事实一个家）。
