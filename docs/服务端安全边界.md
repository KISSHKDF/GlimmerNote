## 0. 一句话边界

只服务**本机浏览器上的自家页面**：绑 `127.0.0.1`、只认本机 `Host`、只认同源 `Origin`、浏览器访问 `/api/*`
还要带**本轮启动随机生成**的 token；静态下发先过**类型准入**（`2026-11-03` 起：库内只放图片扩展名与两个
有消费者的文本，其余一律 403 —— §5.1），过了准入的库内响应再一律按"不可信文档"处理
（`sandbox` + `default-src 'none'` —— §4），且带大小上限与 `no-store`。
唯一例外是**程序入口** `index.html`（它要执行 `host.js`），走 §4 的 `APP_CSP`。

**它挡的是**：本机任意网页（含 `<iframe sandbox>` 这种不透明源）、DNS rebinding、越界读库外文件。
**它挡不住**：同机任意进程（能读本机文件、能自己造请求、能读服务端进程状态）。后者不是 HTTP 层能解决的，
见 §8。这条边界写在这里，是为了不让读者把"加了 token"误读成"这台机器上就安全了"。

## 2. 入口三道门（顺序固定，任一道不过就退出）

三道门都在 `http.createServer` 的 handler **最前面**，且整段 handler 包在 `try` 里（见 §7 畸形 target）。

| 顺序 | 门 | 判据 | 位置 |
|---|---|---|---|
| ① | **Host / authority**（S05，DNS rebinding 的服务端必要条件） | 只接受主机名 `127.0.0.1` / `localhost`；端口可省，**写了就必须等于本实例 `PORT`**。刻意不做任何模糊匹配（不认 `127.0.0.1.evil.com`、不认 `localhost.`、不认 IPv6 形态——rebinding 靠的就是"域名看起来像本机"）。不放行时**不带上 origin** 回 ACAO。 | `ALLOWED_HOSTNAMES` `:401`、`hostVerdict()` `:402-414`、调用点 `:731-735` |
| ② | **Origin 白名单**（S02） | 只认两种：**无 Origin**（同源请求 / `curl` 这类非浏览器客户端；浏览器对同源 GET 也不发 Origin）与 `ALLOWED_ORIGINS`（`http://127.0.0.1:PORT`、`http://localhost:PORT`）。**`Origin: null` 一律 403**——`null` 不是"file:// 专用标记"，而是**所有不透明源**（攻击者页面里的 `<iframe sandbox>`）共同的字符串，HTTP 层不可区分。读路径与写路径一视同仁。 | `ALLOWED_ORIGINS` `:370`、`corsOrigin()` `:381-385`、`originTrusted()` `:387`、调用点 `:736-740` |
| ③ | **随机 token**（S02 纵深） | 见 §3 | `:749-759` |

**取舍（§4 要回答的那件事）**：既然有 Host + Origin 白名单，为什么还要 token？因为 `Origin` 是**浏览器替我们填的自述**，
本机任何程序都能自己造请求行 —— 对"本机另一个进程 / 用户顺手开的调试工具 / 别的程序里内嵌的 WebView"这一类，
Origin 门禁没有鉴别力。token 挡的是这条路。
**代价**：`file://` 直开的页面不再能连服务端（它读数据需要 `ACAO: null`，而那个已经被取消）。三形态里 `file://` 走桌面壳
`postMessage` 通道；server 模式只服务 `http://127.0.0.1:PORT/` 这个同源页面。

## 3. 随机 token 的适用范围与残余风险

| 项 | 判据 | 位置 |
|---|---|---|
| 生成 | **每次启动一枚** `crypto.randomBytes(24).toString('hex')`；不是常量、不写盘、不跨进程共享 | `const TOKEN` `:428` |
| 请求头 | `X-CTB-Token`（`x-ctb-token`） | `TOKEN_HEADER` `:429` |
| 签发口 | **只有一处**：服务**程序根那份 `index.html`** 时把 `<meta name="__ctbToken" content="…">` 注入到 `</head>` 之前；页面里的 `host.js` 再用 DOM 读出它、带回请求头（唯一出口 `apiFetch`）。**2026-11-03 改动**：形态从内联 `<script>window.__ctbToken=…</script>` 换成 meta —— 程序页补了 `script-src 'self' file:`（无 `'unsafe-inline'`）之后，内联注入会被页面自己的 CSP 拦掉，整站 `/api/*` 变 403。安全性不减：XSS 本来就读得到 `window.__ctbToken`。 | 注入分支 `serveStatic` `:693-708`（`isRootIndex` 判定 `:188`）；响应带 `Cache-Control: no-store`（token 每轮都变，缓存住 = 重启后页面全 403） |
| 哪一份 index.html 才算"程序根" | 判据 `isRootIndex(abs)`：`APP\index.html` **或** `realpath(APP)\index.html`（本机有把 `app` 目录做成 junction 的布局，只比其中一个会漏注入） | `isRootIndex` `:186-190` |
| 强制范围 | **只限** `/api/*` 且**只对浏览器发起的请求**强制。判据 `looksLikeBrowser(req)` = 带任一 `Sec-Fetch-*` 头（浏览器独占的一组头，非浏览器客户端造不出来也不必造）。`curl`、本仓 `tests\neg-server-*.cjs` 的原始 socket / `http.request` **不强制** | `looksLikeBrowser()` `:431-434`、`const isApi` `:752`、调用点 `:753` |
| 比较方式 | 定长比较 + `crypto.timingSafeEqual`（不给"按响应时间逐位猜"留便宜） | `tokenVerdict()` `:436-441` |
| 预检 | `OPTIONS` 的 `Access-Control-Allow-Headers` 必须列 `Content-Type, X-CTB-Token`（白名单来源仍可能带它） | `:760-768` |
| **残余风险（明写）** | **同机任意进程 `GET /index.html` 就能拿到 token。** 这挡不住"同机恶意进程"——那本来就不是 HTTP 层能解决的；它挡的是**本机网页**与**DNS rebinding**这两条真实可用的通道（也就是外部审计 S02/S05 指的那两条）。 | `TOKEN` 段注释 `:416-427` |

## 4. 库内文档的两道纵深：**类型准入**（不进门的文件没有 CSP 问题）+ `sandbox` + `default-src 'none'`（R1）

> **2026-11-03 起这一节的定位变了，先读这段再读下表**：改前这里是"库内文档的唯一防线"——`sandbox` 让它不执行脚本、
> 不读同源资源。但**防线的前提是"文档能被打开"**。R8 整改③ 之后（§5.1 的类型准入），库内**文档型文件**
> （`.html`、`.svg`、`.pdf`、无扩展名…）**根本不再下发**（403），所以第一道防线是"进不了门"，
> 本节讲的 CSP 退为**第二道纵深**：它仍然挂在**每一条**非程序根的静态响应上
> （`addCommonHeaders(res, origin, {sandbox:true})`），管的是"**将来**被放行的任何文档型类型"——
> 现在仍然会被浏览器当文档打开、因而这条判据仍然承重的只剩 `错题记录.md`（`text/markdown`）。

根因（已实测）：用户库里的 `.html/.svg` 是"外部 AI 的产物 + 用户自己存的网页"，不是程序代码，而服务端与程序页面**同源**。
只有 `sandbox` 时脚本确实不执行、读不到同源资源，但 `sandbox` **只禁执行、不禁取** —— 打开一个含远程 `<img>`/`<link>`/`@import`
的库内 HTML 照样把 IP/时间/UA 交给写它的人（ws1-http 2026-11-02 用本机计数器抓到 8 条真实出站，8/8 到达对端）。
**这段历史保留**：它是 `LIB_CSP` 为什么长成现在这个形状的依据，即使它守的那类文件今天已不再下发。

| 项 | 判据 | 位置 |
|---|---|---|
| 库内响应 CSP | `sandbox; default-src 'none'; img-src http://127.0.0.1:PORT http://localhost:PORT data:; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` | `LIB_CSP` `:499-500` |
| 程序入口 `index.html` | `default-src 'none'; script-src 'self' file:; style-src 'self' file: 'unsafe-inline'; img-src 'self' file: data:; connect-src 'self' file:; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`（**不加** `sandbox`：那是程序入口，`host.js` 必须能执行） | `APP_CSP` `:496-497` |
| **同一串必须在两处逐字相同** | `index.html` 的 `<meta http-equiv="Content-Security-Policy">` 与 `APP_CSP` 逐字一致（壳的 `file://` 模式没有响应头，只能靠 meta；服务端模式两份同时生效、取交集） | `src\app\index.html`；机读对拍在 `tests\neg-server-csp.cjs` |
| 谁拿哪一份 | `addCommonHeaders(res, origin, {sandbox:true})` 才发 `LIB_CSP`；判据是 realpath 之后位于**库根**（而不是程序根） | `addCommonHeaders()` `:502-521`（`:515` 选 CSP）；调用点 `serveStatic()` `:711` |
| 为什么**显式列**来源而不用 `'self'` | `sandbox` 让文档变成不透明源（实测 `window.origin === 'null'`，`localStorage`/`cookie` 抛 `SecurityError`），不透明源下 `'self'` 匹配不到 `http://127.0.0.1:PORT` ⇒ 本地题图/证据图会被一并拦掉（全库破图）。端口用运行时常量拼，**不写死** | 同上注释 `:460-475` |
| 为什么必须有 `data:` | 真库 `html/svg/css` 普查（2026-11-02）确有 **1 处** `data:` URI 图（`国庆假期作业1\第4题-错题卡.html`） | 同上 |
| 为什么 `script-src` 一条都不列 | 不列 ⇒ 继承 `default-src 'none'`：内联脚本不执行，外链 `<script src>` 连**请求**都不发 | 同上 `:470-475` |
| 其余公共响应头 | `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、CORS 只回显白名单 | `addCommonHeaders()` `:502-521` |

守它：`tests\neg-server-lib-csp.cjs`（**2026-11-03 按新契约改造**，判据分两段）——
① 第一道纵深：库内 `.html` / `.svg` 请求必须 **403** 且响应体**不含文件内容**（文档型攻击面已关闭），
并用真 headless Edge 导航到库内 `.html` 实证"拿到的不是那份文档 + 外站计数器 0 命中"；
② 第二道纵深：对**仍可下发**的库内文件断言响应头 CSP **逐字等于 `LIB_CSP`**、且**逐字不等于 `APP_CSP`**，
程序根 `index.html` 反向断言等于 `APP_CSP`（防"两边一起退化成同一个值"），
并含"把 `o.sandbox ? LIB_CSP : APP_CSP` 改成一律 `APP_CSP` ⇒ ②必须变红"的阴性自证。

## 5. 静态路由白名单：四道前缀拒 + 一道类型准 + `no-store`（R2 / R8）

判据的输入是**请求 URL 解码后的相对路径**（不是 realpath 的结果）：junction/symlink 逃逸由 §5.2 的包含性判据管；

## 6. 上限与 `Range`：两个 413，别混

同一个状态码 `413` 对应**两件不同的事**，改的时候不要只看一个数：

| 对象 | 上限 | 行为 | 位置 |
|---|---|---|---|
| **请求体**（`POST /api/*`） | **2 MiB**，按 **`Buffer.length`（字节）** 计 | 先看 `Content-Length`，明知超限**立刻**回 413（不吃 body）；边收边按字节计；超限不再 `req.destroy()`（改前客户端只看到 `ECONNRESET`，读不到任何原因） | `MAX_BODY` `:679`、`readBody()` `:685-701`、413 回执 `:869-872` |
| **静态下发**（单文件） | **64 MiB** | 超限回 413 + 明确文案（`file too large …`），不再"能读就整份读进内存"（改前 256 MiB 文件让工作集 +256.3 MB 且不归还） | `MAX_STATIC_BYTES` `:507`、判定 `serveStatic()` `:613-620` |

`Range` 只支持**单段**（含两个合法缩写），并与 `Accept-Ranges: bytes` 配套：

| 输入 | 响应 |
|---|---|
| 无 `Range` | 200 全量 + `Content-Length`（流式下发，不再整份读进内存） |
| `bytes=a-b` / `bytes=a-` / `bytes=-N` 且**可满足** | 206 + `Content-Range: bytes a-b/total` |
| 合法单段但**不可满足**（起点 ≥ 文件尾 / 后缀长度为 0 / 空文件） | 416 + `Content-Range: bytes */total` |
| **非法 spec 或本轮不支持**（单位不是 `bytes`、语法坏、末位 < 首位、多段 `bytes=0-1,5-6`） | **忽略该头、回 200 全量**（RFC 7233：416 的语义是"spec 合法但一条都不可满足"；非法 spec 与合法多段都不属于这一类。改前是"任何 Range 都回整份、无 `Content-Range`"，现在至少**声明**了 `Accept-Ranges: bytes` 并把四类行为分开） |

- 实现：`parseRange()` `:555-580`、`serveStatic()` 的 Range 分支 `:581` 起（`Accept-Ranges` `:663`、413 判定 `:626-632`、416 `:668`、206 `:676`、`fs.createReadStream` `:681`）。
- 守它：`tests\neg-server-static-stream.cjs`（64 MiB 上限触发 413；206 三段；416 三段：越界单段 / 后缀长度为 0 / 空文件；**忽略组 200 全量且无 `Content-Range`**：`bytes=abc` / 多段 / 末位<首位 / 单位非 bytes / `bytes=-`；全程服务端 RSS 增幅 < 32 MiB）；
  请求体侧在 `tests\neg-server-bad-target.cjs`。

## 7. pending 新鲜度判据（R8）与"失败必须说失败"

`GET /api/state` 必须**只读**：pending 分区只在台账**真的变了**的时候才 spawn `_状态刷新.mjs`
（改前每次 GET 都同步 spawn 并整份重写 1.35 MB 状态包）。

| 情形 | 判据 | 结果 |
|---|---|---|
| `_待确认.json` stat 不到 | 台账没了 / 权限变了 | `{status:'unreadable'}` → 响应带 `pendingStale:true` + `degraded` 说明（**不许**静默返回过期 pending） |
| 无记录，或记录里**没有 `hash`** | 生成器刚重写过状态包 / 老记录 | `stale`（保守方向：宁可多刷一次，绝不漏） |
| `rec.mtimeMs === st.mtimeMs && rec.size === st.size` | 快速路径，**不读盘** | `fresh` |
| 内容哈希相等 | `sha1(内容)` **前 16 位**（与 `_状态刷新.mjs::pendingFingerprint` **同算法、同截断**） | `fresh` —— 这条才是内容级判据：`touch` / 以相同字节重存 / 从副本还原**都不算变** |
| 其余 | | `stale` |

- 实现：`pendingHash()` `:252`、`pendingFreshness()` `:253-265`；指纹写入方
  `src\tools\_状态刷新.mjs::pendingFingerprint()` 与 `pendingIsFresh()`。
- 为什么必须两边同算法：改前服务端只比 stat、刷新器是哈希优先 ⇒ 两者互相抵消，
  `_状态.json._pendingSrc.mtimeMs` 永远停在旧值，"内容没变但 mtime 变过"这个**可达状态**下退化成
  **每次 `GET /api/state` 都同步 spawn 一个子进程**（实测 81/74/79 ms vs 内容真变后的 1 ms，而这是页面启动/刷新的最高频路由）。
- 刷新本身**不阻塞事件循环**（R6）：`spawn` 收集 stdout（等价 `maxBuffer` 上限、120 s 超时后 kill 并**报失败**）、
  in-flight 复用（并发请求共用一个子进程）、`stderr` **继承**（`[pending] …` 行是"到底有没有被 spawn"的现场证据）。
  实现：`refreshPendingSection()` 起。
- **失败必须说失败**：状态包读不出 → 响应带 `degraded:'state-unreadable'` + `stateStale:true` + `degradedDetail`，
  且**不更新** `_diskM`（下一次 GET 重试，不会因一次读失败永久降级）。
- 守它：`tests\neg-server-pending-fresh.cjs`（touch 不改内容 → 第 2/3 次 `GET /api/state` **不得**再 spawn；
  改内容 → 必须刷新且 `_pendingSrc.hash` 更新）、`tests\neg-server-refresh-nonblocking.cjs`（慢桩 6 s 期间
  `/health` 必须 < 500 ms）、`tests\neg-server-get-readonly.cjs`、`tests\neg-server-bom.cjs`。

## 9. 明确**不**在边界内（写清，避免被读成"全覆盖"）

1. **同机任意进程**：能读本机文件、能自己造请求、能读 token 的进程不受这些门约束。这不是 HTTP 层能解决的，
   也不打算用"再加一层"假装解决。
2. **不做远程访问**：不监听非回环地址、不做 TLS、不做账号体系。想远程用得走别的通道（不在本项目范围）。
3. **不净化库内文件内容**：CSP + `sandbox` 是"按不可信文档处理"，不是"清洗用户文件"。库里的 `.html` 仍然可以被
   用户在本地浏览器里双击打开（那时与本服务端无关）。
4. **不做内容级隐私扫描**：静态下发的 `no-store` 只影响缓存，不判断文件里有没有敏感内容。隐私机检在
   `tests\repo-hygiene.cjs`（覆盖范围与**未覆盖范围**都在它的输出里）。
5. **签名 / SBOM / 供应链证明**：不在本文件范围，见 `docs\等级与NA清单.md` 与
   `src\shell\webview2-deps.lock.json`（第三方二进制的受控预期哈希）。

## 10. 变更纪律（改判据的人看这一节）

1. **改判据 = 改本文件**：判据在代码里，说明在本文件里；两者不一致时先改本文件到与代码一致，再决定要不要改代码。
2. **每条判据都有守它的用例**（§11）。改判据而不改用例，等于把闸门拆了还留着"已通过"的牌子。
3. **阴性自证是硬要求**：新增/修改的判据必须配一条"把它掏掉，缺陷必须复现"的对照，否则无法证明这条用例有牙齿。
4. **不要用"放宽到能过"解决红灯**：判据写在这里就是为了被引用；要放宽，先在这里写清为什么，再改代码。
5. **行号会漂**：本文件的行号是快照，「定位以符号名为准」这条规则本身也不要改。
