## 〇、一页纸

| 问题 | 一句话答案 |
|---|---|
| 一道题在整页原卷上的位置怎么记 | `regions[]` 里一条 `{role,x,y,w,h,pageSha,imgW,imgH}`，坐标**归一化 0~1** |
| 为什么要记宽高 | 没有 `imgW/imgH` 就**无法把 0~1 反算回像素**——灯箱画框、裁图复算全部落空，所以缺了判红 |
| 一张题跨两页怎么办 | 写**多条** region，每条引用**它自己那张**原图（各自的 `pageSha` 与各自的 `imgW/imgH`） |
| 历史数据（像素 `box`）怎么办 | **读取时归一化**（输出附加 `boxNorm/imgW/imgH`），**磁盘旧值一个字不改**、不迁移 |
| 谁判 | 区域：`regionsOk()`（`门禁` 报红）；换算：`_区域坐标.mjs`（纯函数，零副作用） |
| 与经验包什么关系 | `cases/<caseId>/expected.json` 里凡带坐标，**同一个坐标系、同一个区域对象** |

## 一、区域对象

`_原卷台账.json` 条目上的 `regions[]`，每项一个区域对象：

```json
{
  "role": "错误位置",
  "x": 0.08125, "y": 0.23333, "w": 0.4, "h": 0.16667,
  "pageSha": "3f1c…（64 位十六进制）",
  "imgW": 1600, "imgH": 1200
}
```

| 字段 | 类型 | 必需 | 含义 | 缺失/非法 |
|---|---|---|---|---|
| `role` | 字符串 | 是 | 角色，见 §二 | 不在枚举内 ⇒ **判红**（`role-unknown`） |
| `x` / `y` | 数 | 是 | 区域左上角，**归一化** 0~1 | 非有限数、`< -ε` 或 `> 1+ε` ⇒ 红（`bounds`） |
| `w` / `h` | 数 | 是 | 区域宽高，**归一化** 0~1，`> 0` | `≤ 0`、`> 1+ε`、`x+w > 1+ε`、`y+h > 1+ε` ⇒ 红（`bounds`） |
| `pageSha` | 字符串 | 是 | 该区域所属**整页原图**的内容 sha256 | 不是 64 位十六进制 ⇒ 红（`pagesha`） |
| `imgW` / `imgH` | 正整数 | 是 | 该原图的**显示宽高**（像素，JPEG 已应用 EXIF 方向） | **缺 ⇒ 红**（`imgw-missing`）；非正整数 ⇒ 红（`imgw-nonpositive`） |

`ε = 0.001`（坐标按 5 位小数舍入，最大舍入误差 5e-6，留三个数量级余量；与 `_原卷台账.mjs::boxOk()`
对下界的 `-0.001` 同口径）。**上界刻意不用 `boxOk` 的 `1.02`**：区域的越界就是渲染时画出纸外的框，
2% 的宽容在 1600px 宽的页上是 32px，不能算"手抖"。

判据是**纯函数**（`regionsOk(regions)`，零 IO）：它只看数组自身，不去读盘、不查哈希。
`regions` 字段**不存在** ⇒ 合规（旧记录照旧，见 §六）；存在但不是数组 ⇒ 红（`regions-not-array`）。

## 二、角色枚举

| `role` | 用在哪 | 例 |
|---|---|---|
| `错误位置` | 这道题**错的那一处**在卷面上的位置（裁图/灯箱对准的目标） | 第 18(4) 题的作答行 |
| `公共条件` | 解题**必读**、但不属于这道小题卷面块的公共题干/大前提 | "已知 f(x)=…（本大题共用）" |
| `配图` | 题目自带的图（几何图、电路图、表格） | 第 5 题右上角的函数图像 |

至少这三个；**新增角色必须同时改三处**：本表、`_原卷台账.mjs::REGION_ROLES`、`tests\neg-region-contract.cjs`
的角色用例。不在这三处登记的角色一律判红——宁可红，不许"未知角色当默认放行"。

## 三、归一化 0~1 的语义

**相对「该区域所属的那张原图」自身的显示像素**，不是相对屏幕、不是相对裁图、不是相对 A4。

```
归一化 → 像素：  px = x * imgW,  py = y * imgH,  pw = w * imgW,  ph = h * imgH
像素 → 归一化：  x  = px / imgW, y  = py / imgH, w  = pw / imgW, h  = ph / imgH
```

| 规矩 | 为什么 |
|---|---|
| 分母**永远**是该区域自己那张图的 `imgW/imgH` | 跨页时两张图宽高不同，混用分母 = 框画到别人的页上 |
| 坐标**只**以 5 位小数落库（`round5`） | 与 `_待确认.mjs::parseNormBox()` 同一口径，避免"同一个框存成两种字面" |
| 往返误差 ≤ 1px | 5 位小数在 10000px 宽的图上误差 ≤ 0.05px；用 `boxNorm[i] * imgW` 复算原像素框必须落在 ±1px 内（用例逐条断言） |
| 不存像素原始值 | 一是同一张图可能被换成不同分辨率的重扫件；二是像素值会被误当 0~1 用（T187~T192 的原事故） |

## 四、`imgW/imgH` 为什么**必需**

**没有显示宽高，坐标就是一个不可复算的数**。三个具体后果：

1. **灯箱画不出框**：前端拿到的只有 0~1，必须先知道图的实际显示宽高才能换算出 `<img>` 上的像素位置。
   今天 `_待确认.json` 走的是"像素 box + 浏览器按天然尺寸算"的老路，两套混用就会缩成 1 像素点。
2. **JPEG 方向会翻车**：带 EXIF `orientation=5..8` 的卷面照，**存储宽高与显示宽高是交换的**。
   只记一个数（或记存储宽高）时，横拍的照片画出来的框会整体错位 90°——这正是 `_图尺寸.mjs::displaySize()`
   存在的理由，所以 `imgW/imgH` 的定义被钉成"**显示**宽高"。
3. **复算/迁移时无法自证**：把区域搬到另一份原图（重扫、压缩、旋转校正）时，唯一可用的判据是
   "按 `imgW/imgH` 反算出的像素框是否与证据图上的内容对得上"。缺这两个数，任何迁移都只能靠猜。

所以：**缺 `imgW/imgH` 判红**（`imgw-missing`），`0` 不是"不知道"的合法写法——那等于把一个错误坐标
伪装成合法坐标。这与教训 L-530（缺失字段不许当值）同一条纪律：量不出来就给**原因**，不给 0。

## 五、`pageSha` 与跨页规则

- `pageSha` = 该区域所属**整页原图**（不是裁图！）的 sha256，**大写或小写十六进制、64 位**，落库统一**小写**。
- **跨页 ⇒ 写多条 region**，每条引用**它自己**那张原图：自己的 `pageSha`、自己的 `imgW/imgH`。
  不存在"一条 region 跨两页"的写法——那样的框在任意一张图上都画不出来。
- **跨页引用错**的判据（`cross-page`）：同一个 `pageSha` 在同一个 `regions[]` 里出现多次时，
  各条的 `imgW/imgH` 必须**完全一致**。同一张图不可能有两个显示宽高；出现两个就说明其中一条
  其实引用的是另一张图（典型事故：把 A 页的宽高抄到 B 页的 region 上），此时两条都不可信。

> 为什么不校验"`pageSha` 必须等于台账条目 `e.page` 那张图的哈希"：跨页是合法形态（B-07 案例里
> 公共条件就在下一页），`regions[]` 可能包含**不属于 `e.page`** 的区域，而区域对象里没有页码字段，
> 只有 `pageSha`。硬绑 `e.page` 会把合法跨页判红。真正的全链对账（`pageSha` ↔ 保全库里有这个字节）
> 属于批次 4 的"区域落库 + 原图并排显示"，不在本文件的判据范围内。

## 六、`_待确认.json` 的像素 `box`：读取时归一化，磁盘**不迁移**

`_待确认.json` 的 `box` 是**源图像素** `[x,y,w,h]`（历史遗留，真库里几十条）。处置：

| 阶段 | 做法 |
|---|---|
| 磁盘 | **一个字不改**。不批量改写、不加 `boxNorm` 字段落盘、不改 `box` 的语义 |
| 读取（`_待确认.mjs` 的 `门禁 --json`） | 每条附加 `boxNorm`（0~1，5 位小数）+ `imgW` + `imgH` |
| 读取（`_服务端.mjs` 的 `GET /api/state`） | pending 条目附加**同样三个字段**（import 同一个实现，不写第二份） |
| 量不出尺寸时 | 只附 `boxNormWhy`（**具体原因**，含图路径），**不写** `imgW/imgH`——绝不给 0 |
| 没有像素 `box` 的条目 | **一个字段都不加**（旧形状原样，前端旧路径不受影响） |

为什么不迁移：

1. `_待确认.json` 是**用户真源**（人工判读留痕），批量改写真源的风险远大于收益；
2. 旧值的像素语义依赖"当时那张证据图"，图可能已经被重裁/替换——迁移动机不成立；
3. 读取时换算**零风险**：磁盘不变，任何时刻都能撤回；旧题没有坐标也照样展示（走老路）。

`boxNormWhy` 的三种原因（都带**图路径**，不许只说"失败"）：

| 情形 | `boxNormWhy` 内容 |
|---|---|
| 条目没有 `evidence` 路径 | `没有证据图路径，量不出显示宽高` |
| 证据图不在盘（或含通配符） | `证据图不在盘：<绝对路径>` |
| 文件在、但读不出宽高 | `读不出文件头（格式不支持或文件损坏）：<绝对路径>` |
| 像素框本身非法 | `boxPx 不是 4 个有限数字：…` / `红框宽或高 ≤ 0：…` / `红框超出图片范围（图 1600x1200，框 …）` |

已知边界（诚实写明）：像素框 `[0,0,1,1]` 与"1×1 像素的合法框"无法区分，换算层不判它非法；
这一类由 `_待确认.mjs::alignAudit()` 的 `boxProblem()` 点名（"红框是 0~1 归一化值，却被按像素使用"）。

## 七、判据与实现位置（谁判、判什么）

| 判什么 | 在哪 | 形态 |
|---|---|---|
| 区域对象合规（角色/边界/必需宽高/`pageSha`/跨页一致） | `src\tools\_原卷台账.mjs::regionsOk(regions)` | 纯函数；`门禁` 路径逐条报红并给**具体原因**；角色枚举同文件导出的 `REGION_ROLES` |
| 像素 ↔ 归一化换算、显示宽高测量 | `src\tools\_区域坐标.mjs` | `boxNormOf(boxPx,imgW,imgH)` / `normEvidenceBox({boxPx,imgAbs})`，**唯一实现**（导出还有 `evidenceAbs(rel,root)` 与容差常量 `BOX_PX_TOLERANCE`） |
| 台账重建不许吃掉 `regions[]` | `src\tools\_原卷台账.mjs::build()` | 重建前**显式断言**（P1-1 的未知字段透传），吃掉就报错退出、不写盘 |

`regionsOk()` 的错误码（`门禁` 输出形如 `<学生|卡号> 区域[2] 非法（bounds）：x+w=1.03 > 1+ε`）：

| code | 触发 |
|---|---|
| `regions-not-array` | `regions` 存在但不是数组 |
| `region-not-object` | 数组元素不是对象 |
| `role-unknown` | `role` 不在 §二 枚举 |
| `bounds` | `x/y/w/h` 非有限数、越界、`w/h ≤ 0`、`x+w/y+h` 超 `1+ε` |
| `imgw-missing` | 缺 `imgW` 或 `imgH` |
| `imgw-nonpositive` | `imgW/imgH` 不是正整数 |
| `pagesha` | `pageSha` 不是 64 位十六进制 |
| `cross-page` | 同一 `pageSha` 的两条 region 给了不同 `imgW/imgH` |

`_区域坐标.mjs` 的两条纪律（模块级，别改）：

1. **零导入期副作用**：不 import `_库根.mjs`、不求值库根、不抢库锁、不读写用户库。
   原因见 `_配方.mjs:46-52` 与本仓反复付过的学费：导入期求值库根会让 `--data`/`CTB_DATA` 直接失效，
   而"服务端 import 一个会抢库锁的模块"等于给自己埋死锁。
2. **只读文件头**：测量走 `_图尺寸.mjs::displaySize()`（PNG/JPEG/GIF/BMP/WebP，JPEG 应用 EXIF 方向），
   不做完整解码、不写缓存进库根。

## 八、与经验包 `cases/<caseId>/expected.json` 的关系

**同一坐标系、同一区域对象。** 经验包案例里的"错误位置 + 解题必需条件"就是 §二 的 `错误位置` +
`公共条件` 两个角色，坐标一律归一化 0~1 + `imgW/imgH`，跨页照样拆多条。

分家规矩（一份事实一个家）：**本文件钉坐标系与判据**；`expected.json` 的**字段表**由经验包规范登记
（`docs\经验包规范.md`）。两边冲突时以本文件的坐标系与判据为准，并由经验包侧改字段表。

## 九、与 `_原卷台账.json` 的关系（一处真源）

- 区域字段住在 **`_原卷台账.json` 的条目上**（键 = `学生|卡号`），与 `page`/`box` 同一个对象、同一次原子写、
  同一把库锁。**不新建第二份"区域台账"**（决策见施工方案 D2）。
- **不改** `_原卷台账.json` 的 `doc.version`（现为 `1`）。施工方案 §7 把带 `regions[]` 的形态称作"v2"，
  但那是**语义上的**第二代：`regions[]` 是条目级**附加**字段，不认识它的旧读者行为一字不变（P1-1 的
  未知字段透传保证重建不丢）；把 `version` 从 1 抬到 2 只会让"认版本号"的旧代码整份拒绝，收益为零。
- 重建（`生成` / `采集` / `合并`）**不许**吃掉 `regions[]`：`KNOWN_CARD_FIELDS` 白名单里**没有** `regions`
  的位置就是对的，且 `build()` 里有显式断言兜底（吃掉即报错退出，绝不静默写盘）。
- `门禁` 对没有 `regions` 的条目**零变化**（不打印、不计数、退出码不变）。

## 十、兼容红线（本契约的验收口径）

| 红线 | 判据 |
|---|---|
| 旧记录没有 `regions` ⇒ 一切照旧 | `门禁`/`生成`/`覆盖` 的输出与退出码逐字节不变 |
| 只许**附加**字段 | `/api/state`、`门禁 --json` 的**旧字段一个不改**；新字段缺失时前端旧路径照跑 |
| 磁盘旧值一个字不改 | `_待确认.json` 的 sha256 在读取/门禁/服务端 GET 前后完全相同 |
| 不许量不出当 0 | 量不出尺寸时 `imgW/imgH` **不出现**（不是 `0`），且给 `boxNormWhy` |
| 唯一实现 | 归一化除法只许出现在 `_区域坐标.mjs`；`_待确认.mjs`/`_服务端.mjs` 只 import 它并**附加**字段（`tests\neg-region-contract.cjs` 的 ⑤ 两处对拍 + ⑦ 静态断言守着） |
