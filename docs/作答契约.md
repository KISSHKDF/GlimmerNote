# 作答契约（答案齐全 · 图上作答 · 横线够宽）

> 立规日：2026-10-25 ｜ 起因：用户同一天三条报障，原话级
> ｜ 裁判：`src\tools\_作答门禁.mjs`（唯一入口）｜ 回归：`tests\neg-answer-slot-contract.cjs`
> ｜ 渲染：`src\app\js\model.js`（`slotsOf / needEm / blankWidthEm / applySlotWidths / stemFit`）+ `views\paper.js`

## 〇、横线宽度口径：答案所需 × 1.5（2026-10-25 晚二次报障定档）

> 用户原话（语文默写 Y0003《行路难》默写）：「给出的横线明显不够写答案…… 再考虑到小孩子写字
> 不规矩，你再放一个 **1.5 倍**的带下横线的空格出来，这才是合理的出题方式」。

| 量 | 含义 | 谁算 |
|---|---|---|
| `needEm(answer)` | 这条答案按**成人字迹**排下来要几 em（字宽和 + 1.2em 尾余） | `_空位.mjs` / `model.js`（同判） |
| `blankWidthEm(answer)` | **横线至少要几 em** = `needEm × CHILD_FACTOR(1.5)`，并夹在 `BLANK_MAX_WIDTH_EM(30em)` 内 | 同上 |
| `BLANK_MAX_EM = 18` | 判"该不该换 zone"的上限（答案本身 >18em ⇒ 一行横线塞不下） | 同上 |

为什么是 1.5 倍：Y0003 那个空 7 个字，旧口径给 8.2em（12.5pt 正文 1em ≈ 4.41mm ⇒ 36mm，
**5.2mm 一格**）——成人楷书约 3.5–4mm/字，孩子的手写 6–8mm/字，所以"刚好写满"等于"一定写不下"。
1.5 倍后 12.3em ≈ 54mm，**7.7mm 一格**，写完还有余量。

为什么还有 30em 上限：A4 可用宽 178mm ≈ 40em，单条横线再宽就只能换行、甚至溢出纸面；
超长答案（整段话）按 §三 第 4 条本就该改判 `zone`（`18 × 1.5 = 27 < 30`，合规卡的横线永远够用）。

## 一、为什么要有这份契约

三条报障看起来是三件事：

| 原话 | 表面症状 | 实际根因 |
|---|---|---|
| 「M0066，答案好像不全」 | 答案册里那道填表题只写了后半两张表的答案 | 题干有 **10 个空**，答案只是"一段话"，没人知道它漏了哪几个 |
| 「M0011，在图上写出答案，所以组卷时这类题目不需要再留答题区」 | 集合填数题的卷面上白印了一个 220px 大空框 | 题目**答案写在图里**，而渲染器只会按题型猜答题区 |
| 「M0084，给出的下横线长度根本不够写答案」 | 6em 的横线，答案「−a 的相反数是 a」约 9em | 横线宽度是**手写死的排版值**，跟答案长度没有任何关系 |

同一个根：**题干里的"空"从来没有被当成数据**。渲染器只是把下划线画出来；
没有任何地方知道"这道题有几个空、每个空的答案该多长、答案是写在横线上还是画在图里"。
于是三类缺陷都只能在**印出来之后**被用户一题一题点出来——这就是它必须变成制度的原因。

## 二、契约字段（写在 `_索引.json` 的卡片条目上）

```json
{
  "id": "M0066",
  "answerMode":  "blank",
  "answerSlots": ["5", "2", "25", "−1/5", "3", "−1/125", "(−2)⁴", "−2", "(−3)³", "−3"],
  "answerScope": "full",
  "answerSlotsBy": "agent",
  "answerSlotsAt2": "2026-10-25"
}
```

| 字段 | 取值 | 含义 | 不写的后果 |
|---|---|---|---|
| `answerMode` | `blank` / `figure` / `zone` / `none` | 答案写在哪里 | 图里作答的题会被印出大白框（M0011） |
| `answerSlots` | 字符串数组 | **逐空答案，顺序＝卷面顺序** | 答案册只能印一段话，漏空无人知（M0066） |
| `answerScope` | `full`（缺省）/ `partial` | 合卡只考部分空 | 合卡会被要求补齐几十个不考的空 |
| `answerSlotsAt` | 数字数组（1 起） | `partial` 时每个答案对应第几空 | 答案会印到错误的空号上（比缺失更坏） |
| `answerNote` | 字符串 | `partial` 的人话说明，**会印在答案册上** | 家长不知道"为什么只列这几空" |

### 四种作答方式

| mode | 用在哪 | 卷面 | 答案册 |
|---|---|---|---|
| `blank` | 答案写进题干横线（绝大多数填空、默写） | 打印题干，横线按答案撑宽；**不再另留答题区** | 主答案 + 逐空列出 |
| `figure` | 答案要画/写在配图上（集合圈填数、画力臂、标出支点、连电路） | 打印题干，**不留答题区** | 主答案 + 「（本题答案写在图上）批改看图形」 |
| `zone` | 长答/计算/证明，横线塞不下 | 按题型/难度留 90–280px 答题区 | 主答案 + 逐空列出 |
| `none` | 选择、判断（把答案写在题号前） | 0 高匿名区 | 主答案 |

## 三、判据（机器怎么判——全部可复现）

```
node src\tools\_作答门禁.mjs 扫描        # 全库逐卡列出问题
node src\tools\_作答门禁.mjs 门禁        # 硬门禁（退出码 1 = 印出来会出丑）
node src\tools\_作答门禁.mjs 工单 --out <目录>   # 导出逐卡工单（含每空位置/宽度/现有答案）
node src\tools\_作答门禁.mjs 批量 --file <decl.json>
```

1. **空位数是客观事实**：`<span class="blank">`、ASCII 下划线串 `______`、全角 `＿＿`，
   出现在 `<svg>` 之外才算。实现在 `src\tools\_空位.mjs`，浏览器侧 `model.js` 并列一份同判实现，
   两者**逐卡对拍**（`tests\neg-answer-slot-contract.cjs` P 段，419 张卡全量）。
2. **答案齐全**：`answerSlots.length` 必须等于空位数（`partial` 用 `answerSlotsAt` 定位），
   且不得有空串。这一条直接堵住 M0066 那类"只抄了一半答案"。
3. **图上作答**：题干有图 + 题面出现「填在/画在/圈出/标出/在图上/作图」等技术词 ⇒ 必须显式登记
   `answerMode`（`figure` 不留答题区；确实要另写文字才登记 `zone`）。**不允许沉默**——
   沉默就是又印一个白框。
4. **横线够宽**（分两档，口径不同——别把机器能自动修的和必须人决策的混在一个阻断级）：
   - **偏窄** ⇒ 只提示：判据是"声明宽度 < `blankWidthEm`（答案所需 × 1.5）"；
     渲染器每次都按 `blankWidthEm` 撑宽（`applySlotWidths`），印出来一定够写；
     数据侧宽度只是排版基线，`_作答门禁.mjs 修宽` 可把基线也补齐（含 `partial` 合卡，
     按 `answerSlotsAt` 撑到**它自己那一空**——旧版整卡跳过，那批合卡永远是原始排版宽度）。
   - **太长** ⇒ 阻断：单空答案 `needEm > BLANK_MAX_EM = 18`（≈72mm）时，
     不许硬塞横线，必须改判 `zone`（另留答题区）。这是排版**决策**，机器不替人决定。
   - **物理上限**：单条横线一律 ≤ `BLANK_MAX_WIDTH_EM = 30em`（≈132mm），**连题干里声明的宽度一起夹**。
     为什么连声明也夹：早期"按答案撑宽"把 39.2em（≈173mm，超过 A4 可用宽 178mm 减行首文字）写进了题干，
     而"原有宽度是下限"的规则会把它原样保留 ⇒ 那条横线自己就撑出纸面（2026-10-25 晚全库终检抓到 6 处，
     已由 `修宽` 把数据基线也夹回 30em）。代价：这类答案进横线只能占一行——更长的答案本就该判 `zone`。
   - `zone`（答案写在答题区）与 `figure`（答案在图上/是一段画法描述）不做宽度判定。
   - 改 `BLANK_MAX_EM` / `CHILD_FACTOR` / `BLANK_MAX_WIDTH_EM` 必须同时改
     `src\tools\_空位.mjs` 与 `src\app\js\model.js`（两处同值，测试 P3/P3b/P3c 对拍）。

判定有三态：通过 / 阻断（在册卡）/ 归档不阻断但必须可见（沿用本仓惯例）。

## 四、三道闸门（写一次，堵所有入口）

| 闸门 | 位置 | 拦住什么 |
|---|---|---|
| 数据门禁 | `tests\run.mjs` 前置 + `_体检.mjs` 硬门禁 | 库里有不合契约的卡 ⇒ 发版检查单过不去 |
| 组卷口 | `_标记复习.mjs 组卷`（`--force` 才可绕，且会打印警告） | 残缺答案的题根本进不了卷 |
| 渲染口 | `model.js stemFit` + `paper.js qHtml/ansHtml` | 就算数据欠账，纸面也不会出现"窄线/白框/残缺答案册" |

## 五、新增一张错题卡时的动作顺序

1. 写 `题干.html` 时就想清楚：这题**几个空**、答案**写在哪**（横线/图上/答题区）。
2. `node src\tools\_作答门禁.mjs 补登 --card 学生|编号 --mode blank --slots "答案1；答案2"`
   （多条答案用中文分号分隔，顺序＝题干空位顺序；合卡再加 `--scope partial --at "1,3" --note "..."`）。
3. `node src\tools\_作答门禁.mjs 门禁` 必须绿。
4. `node src\tools\_作答门禁.mjs 修宽` 把横线基线一次性按 **1.5 倍**补齐
   （不跑也能印——渲染器会实时撑宽——但数据基线窄就等于把坑留给下一个渲染器）。
5. 组卷时如果被拦，按提示补 `answerSlots`——**不要**用 `--force` 跳过（答案册会缺答案）。
6. 印刷前建议用 `render-check` 之类的方式看一眼真渲染（纸面缺陷只能在纸上看出来）。

## 六、已知边界（契约覆盖不到的地方，门禁会打印出来但**不阻断**）

- **表格里整格空着却没写空位**（如原卷要补「弹簧测力计示数 F/N」两个表头，题干里是两个空 `<th>`）：
  门禁数不到它，只能在题干里补 `<span class="blank">`。`扫描` 会报「表格里有 N 个空格子」。
- **同一处横线被拆成两段 span**（转录时切错）：数得出两个空，卷面只有一处作答。这种卡用 `partial` + `answerNote` 说明。
- **题图自带笔迹**：作图题的 `题图.jpg` 若取自原卷裁图，可能已含孩子画的力/力臂 ⇒ 重做卷等于泄答案。
  已登记待办 T199，修法是重画无笔迹矢量图或只裁印刷层。
- **同一道原题被拆成两张卡**（各记不同空）：`扫描` 会列出同题多卡，组卷别同时抽中。

## 七、为什么不是"我记住下次注意"

因为这三类缺陷的共同特征是**只在纸面上暴露**：屏幕上看题干是好的、数据库里字段是全的，
只有把卷子和答案册印出来才发现少了三个空、多了一个白框、横线写不下。任何"下次注意"都不足以
在 419 张卡上生效。现在它们各自对应一条可跑的断言 + 一个会红的门禁 + 一条组卷拦截，
并且渲染器本身不会再产生这三种形态——**制度替代记性**。

## 八、横线宽度的两次翻车（同一条规则的演化史）

| 时间 | 规则 | 纸面上的结果 | 教训 |
|---|---|---|---|
| 2026-10-25 白天 | 横线 = 答案所需 × 1.0（`needEm`） | Y0003 七个字给 36mm →「明显不够写」 | 「够写」不能用成人字迹的下限来定义 |
| 2026-10-25 晚 | 横线 = 答案所需 × **1.5**（`blankWidthEm`） | Y0003 → 54mm（7.7mm 一格） | 余量要按**服务对象**（小孩的手）定，不是按排版最小可行值定 |

两次是同一个根因的两面：第一次错在"宽度与答案无关"（6em 硬编码），第二次错在"宽度按成人
算够、按孩子算不够"。所以现在这条规则有三条腿：**答案文本**（`answerSlots`）× **1.5 书写余量**
（`CHILD_FACTOR`）× **纸面物理上限**（`BLANK_MAX_WIDTH_EM`），任何一条缺失都会重新出现同一类投诉。
