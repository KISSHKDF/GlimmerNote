## 2026-10-24 · 退役 `tests\neg-v1-stem-sanitize.mjs`

**它原来测什么**：从「首页.html」里抽出 `stemSafe` / `stemAttrs` / `STEM_TAGS`
等函数，在内存里跑投毒样本，验证 v1 版首页的题干净化有效；再用真实库的 419 张卡
验证「净化后文字不被截断」。

**为什么要退役**：

1. **它依赖的文件不在本仓**。它读的是冻结区（v1 旧版）的 `首页.html` ——
   的文件。v1 页面早已下线，`src\` 里根本没有 `首页.html`，也没有
   `stemSafe` / `stemAttrs` / `rawdot` 这些函数（已 grep 全仓确认）。
2. **它保护的是已下线的代码**。v2 的净化实现是 `src\app\js\model.js` 的
   `M.stemHtmlSafe` / `M.filterAttrs`，与之完全无关。
3. **它对发布物零保护**。因为路径写死在冻结区，新克隆上它要么直接报错（F-06），
   要么因为路径恰好不存在而失去意义。**留着它只会制造"有护栏"的错觉。**
4. v2 的净化行为已由 `tests\neg-v2-smoke.cjs` 覆盖（script 连内容剔除、`on*` 属性剔除、
   `javascript:` 拒绝、相对图重写、fig 兜底）。

**退役后失去的覆盖（= 待补的欠账，不掩饰）**：

| 丢失的断言 | 现状 | 补法（未做） |
|---|---|---|
| 「净化后题干**文字不被截断**」（原 419 张真实卡跑过） | 无覆盖 | 应在 v2 上加一条：用 `M.stemHtmlSafe` 处理真实卡的 `stemHtml`，比净化前后去标签文本是否等长。需要把 model.js 在 Node 里加载起来（要 stub `H.asset` / `U.esc` / `M.cardDirOf`） |

这条欠账已登记在本机审计台账（不随仓库分发）的 D-046。

**原文件**：已从仓库移除，仅留在维护者本机的开发历史归档里（那份历史不对外发布）。
