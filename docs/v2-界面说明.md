## 三、不变的铁律（刻意不变）

1. **a2**：不排期、不推送、不强制——nextDue 只是建议日；复习流也不拦你哪天练。
2. **b1**：组卷重做走纸质；屏幕复习流是补充，不是替代。
3. **c1**：错因三层 K/L/S 口径不动；界面对错因代码**不自造含义**，只展示卡上原文。
4. **唯一写入入口**：复习=`_标记复习.mjs`、待办=`_待确认.mjs`、重建=`_生成首页.ps1`；2.0 界面自己**从不直接写任何 JSON**。
5. **盲解门禁**：未过盲解的题不进组卷池/复习流（界面先提示，工具仍是最终裁判）。
6. **泄答案防线**：重做卷只出印刷题干/裁净题干图，原卷截图（带黑笔错解红笔订正）只在翻开答案后出现。

## 四、试用建议路径（10 分钟）

1. 首页看 KPI/待办 TOP5/热力图 → 点「☰ 待办工作台」，找一条「问原卷」点开证据图（会自动对准红框），写结论点「✓ 确认办结」。
2. 顶栏切「学生A」→ 题库浏览：点几个筛选 chip → 点任意一行开抽屉 → 「📄 错题记录.md」→「🔍 大图看原卷」。
3. 「🔁 复习流」→ 题源选「全部未复习」→ 上限 5 → 开始：做题（可 Ctrl+滚轮看不了就跳过思路）→ 空格翻开 → 诚实判分 → 结算点「💾 落库」→ 看 toast 与自动重建。
4. 「🧾 组卷工作台」→ 快捷圈题「全部到期题」或去题库勾选 → 生成试卷预览 → 「🖨 打印」试版式；「📒 台账/回录」看刚才复习流自动生成的批次。
5. `Ctrl+K` 输题号/关键字直达；`?` 看快捷键。

## 五、已知边界（试用版从简）

- 浏览器通道（7187）只支持查看 + 待办办结；复习落库/组卷入账需桌面壳（V2.exe）。
- 判分「转折点笔记」并入批次备注（工具一批一注的既有口径），未做单题字段。
- 深色主题的截图类细节以实际屏幕为准，遇到刺眼处直接反馈即可。
- 数据刷新靠顶栏 ⟳ / 托盘「刷新」/ 落库后自动重建；不做轮询（a2）。

## 六、试用中发现的两件系统级事项（与 2.0 无关，属 1.x 既有隐患，仅报告不擅动）

1. **v1 桌面壳跑「全量重建」有编码隐患**：生成器内部用 PowerShell 调 `node _待确认.mjs 门禁 --json`，
   PS5.1 按系统 GBK 解码子进程 UTF-8 输出 → 待办区中文可能被写成乱码并落盘 `_状态.json`
   （本次实测踩中一次，已用命令行直跑生成器修复并验证干净）。
   **v2 壳已在启动生成器前强制 UTF-8 编码，从根上免疫**；v1 未动——建议今后重建一律用 v2（托盘「全量重建」或顶栏 ⟳ 后重建），或让 agent 代跑。
2. **WebView2 单条消息 1MB 上限**：`_状态.json` 已 857KB 且随台账增长，v1 壳的整包回传方式逼近上限，
   超过约 1MB 后 v1 桌面版会白屏（浏览器/服务端通道不受影响）。**v2 壳已实现分片传输，无此问题**——这也是将来用 v2 替代 v1 的硬理由之一。
