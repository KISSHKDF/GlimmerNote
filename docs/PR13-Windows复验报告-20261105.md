## 六、本轮踩到并已修复的一个事故（重要）

**症状**：在临时 worktree 里跑测试后，worktree 的 `HEAD` 凭空变成测试夹具的提交（`data: 被掏空的版本`）、`git ls-files` 只返回 1 个文件、`git rev-parse --show-toplevel` 报 *"this operation must be run in a work tree"*。

**根因**：主开发树的 `.git\config` 里 `core.bare` 被写成 `true`。bare 状态下 `git commit` 仍会成功、提交进入仓库 refs，工作树却不被跟踪 ⇒ 后续所有 git 操作失效。

**修复**：`git config core.bare false`（先备份 `.git\config`）+ `git reset --mixed <原 HEAD>`（原 HEAD 从 `git reflog` 找回，夹具提交都在 reflog 里）。

**已确认未造成实质损失**：主开发树的 refs / index / 工作区内容**未受影响**（只有 config 一项被改，已修复并复验）；三棵树现均 `core.bare=false`、索引完整（310 文件）、`git status` 干净。

**教训**：在 worktree 里跑测试后**立刻**核对 `git log --oneline -1` 与 `git ls-files | Measure-Object`；主树跑完也查一遍 `.git\config` 的 `bare`。
