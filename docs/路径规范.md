# 路径规范（内部痕迹判据的本项目口径）

> 立：2026-10-24（审计驱动）｜ 对应判据：`GSE-STD` **B-09 内部痕迹**
> 本文的作用：把"什么算违规、什么算合法"写死，免得每轮审计各判一套。

## 一、为什么需要这份口径

B-09 的字面要求是「仓库里不得出现本机绝对路径（注释里的也算）」。
字面执行在本项目上会**恒 FAIL 且毫无意义**：

| 实测（2026-10-24） | 数量 | 性质 |
|---|---|---|
| 可执行代码里的盘符路径 | 10 | 其中 2 处是 `C:\Windows\Microsoft.NET\...\csc.exe`（**系统路径，不是本机痕迹**）；8 处是行尾注释被算进了可执行行 |
| 注释里的盘符路径 | 47 | 绝大多数是**解释历史**：「原先写死 `file:///D:/<旧库>/…`，目录一挪前端就指向不存在的位置」——这是在说明为什么改成自推导，删掉它等于删掉知识 |
| 文档里的盘符路径 | 17 | README「三区模型」**必须**写出开发区/运行区/冻结区三个目录，否则用户看不懂程序与数据是怎么分的 |

把这些全删了，代码不会更安全，只会更难维护。
所以本文把判据拆成三档，只有第一档判 FAIL。

## 二、三档口径

### 档① 可执行代码里的本机绝对路径 → **FAIL**

**定义**：出现在**非注释、非字符串常量以外的执行路径**上的盘符绝对路径
（`D:\...`、`C:\Users\<用户名>\...`），会导致换机即坏。

**必须改**，改法：

- 运行时定位用**自推导**：`src\app\js\host.js` 从页面 URL 推（已实现）
- 脚本内定位用 `$PSScriptRoot`（PowerShell）/ `__dirname`（Node），不要写死
- 测试的数据源走 `tests\_测试环境.cjs` 的 `LIB` / `CTB_DATA`

**允许的例外（不算 FAIL）**：

- **系统路径**：`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`、`C:\Windows\System32\...`
  —— 这是 Windows 的固定位置，不是"本机痕迹"
- **工具链路径**：`C:\Program Files\Go\bin\go.exe` 类，且**必须可从外部覆盖**（见下）

### 档② 注释/文档里的路径 → **允许，但必须说明理由**

**判定**：如果这行路径在**解释一件事**（历史教训、设计取舍、排障线索），允许保留；
如果它只是**顺手写下的本机习惯**（例如"我一般放在 D:\xxx"），应当改成相对说法。

**强制要求**：涉及本机用户名的路径一律**不得出现**（`C:\Users\<真实用户名>`）。
这类是隐私泄露，不论在代码还是注释里都算违规。实测：**当前全仓 0 处**。

### 档③ 文档必须写路径的地方 → **允许**

README「三区模型」、`docs\迁移交接单.md` 这类**面向操作的文档**，
不写绝对路径用户就无法执行。判为合规。

## 三、工具链路径的可覆盖要求

`scripts\build-release.ps1`、`src\shell\build.ps1` 里出现 `C:\Program Files\Go\...`、
`C:\Users\<user>\tools\mingw64\...` 是**当前唯一实现**，但不许写死不可改：

**要求**：每一处硬编码工具链路径都必须满足其一：

1. 先读环境变量（`$env:CC` / `$env:GO`），为空才用默认值；**或**
2. 顶部集中成一个变量，并给出注释说明怎么改

**现状**（2026-10-24）：`src\shell\build.ps1` 用的是**候选列表探测**
（依次试 Framework64 / Framework 两处 csc），已满足要求。

## 四、机器检查

`node tools\lint.mjs` 的 **L2** 规则实现了档①的一部分：

- 只查 `src\app\**` 与 `src\tools\**` 等运行时代码
- 跳过注释行与行尾注释
- 跳过 `tests\` / `tools\`（那里需要构造非法路径做阴性对照）
- 盘符**只认大写**且加左边界守卫（避免把 JS 正则字面量 `key:/re/`、
  正则转义 `max-width:\s*` 当成盘符路径——这个坑实测制造过 78 处假阳，见 D-034/D-043）

**已知能力边界（诚实写明）**：

- 小写 `d:\foo` 会漏检（宁可漏，也不制造几十处假阳——"恒红的检查等于没有检查"）
- 不检查"工具链路径是否可覆盖"（这条靠人工评审）
